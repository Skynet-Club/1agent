## 2. Public API

```rust
pub struct ExportDocument {
    pub value: serde_json::Value,
    pub sha256: String, // SHA-256 of canonical JSON bytes
}

pub enum OntologyError {
    Io(String), Json(String), Session(String), Journal(String),
    Validation(String), Unsupported(String),
}

pub fn export_session(session_root: &Path, session_id: &str) -> Result<ExportDocument, OntologyError>;
pub fn export_journal(journal_path: &Path) -> Result<ExportDocument, OntologyError>;
pub fn validate_document(document: &serde_json::Value) -> ValidationReport;
pub fn builtin_types() -> serde_json::Value;
pub fn builtin_bindings() -> serde_json::Value;
```

`export_session` must not create a session. It must fail with `Session` when the id
does not exist. `export_journal` exports a standalone run without `partOfSession`.

## 3. JSON-LD shape

```json
{
  "@context": { "...": "..." },
  "ontologyVersion": "0.98-draft",
  "bindingVersion": "1",
  "registrySha256": "<sha256 of ontology/types.json bytes>",
  "@graph": [
    {"@id": "urn:1agent:session:<id>", "@type": "Session", "...": "..."}
  ]
}
```

Rules:

- `@context` is embedded (not a URL) so the export is self-contained.
- `@graph` is sorted by `@id`; arrays preserve source order except references,
  which are sorted.
- No `generatedAt`/export timestamp; determinism is more important.
- No raw prompt text, tool `content`, page text, keys, or full file contents.
  `summary` fields are bounded to 500 chars; arguments are not exported.
- `sha256` is computed over the exact bytes of `serde_json::to_vec(&value)`.
  The document itself does not contain its own hash.

## 4. ID rules

| Entity | IRI |
|---|---|
| Session | `urn:1agent:session:<session-id>` |
| Run | `urn:1agent:run:<run-uuid>` |
| Task | `urn:1agent:task:<run-uuid>:main` |
| ToolInvocation | `urn:1agent:tool-call:<run-uuid>:<call-id>` |
| Observation | `urn:1agent:observation:<run-uuid>:<call-id>` |
| Answer | `urn:1agent:answer:<run-uuid>` |
| Claim | `urn:1agent:claim:<run-uuid>:<claim-id>` |
| Evidence | `urn:1agent:evidence:<run-uuid>:<seq>:<index>` |
| Artifact | `urn:1agent:artifact:sha256:<64-hex>` |
| Goal | `urn:1agent:goal:<goal-id>` |
| Commitment | `urn:1agent:commitment:<commitment-id>` |

Segments must be percent-encoded for characters outside `A-Za-z0-9-._~`.
Never use PID/title/path as identity.

## 5. Minimal mapping

| Journal/session source | JSON-LD |
|---|---|
| `session.json` | `Session` |
| `RunStarted` | `Run`, `Task` |
| `ToolCalled` | `ToolInvocation` |
| `ToolObserved` | `Observation`, optional `Artifact` (metadata sha256/path) |
| `AnswerProduced` | `Answer`, `Claim`, `Evidence` |
| `RunStopped.reason` | `Run.hasOutcome` |
| session mission | `Goal` (read-only; status active) |
| `ToolObservation.metadata.policy_*` | `ActionInvocation`/`PolicyDecision` only if present |
| `SubagentRecord` | `SquadMember` (lineage fields optional; P1) |

Source classification for `Evidence.source`:

1. `http://`/`https://` → `web`
2. `tool:` prefix → `tool`
3. `model:` prefix → `model_prior`
4. absolute/relative path with `/` → `file`
5. otherwise → `unknown`

## 6. Validation rules (P0 internal)

- `Run`: `hasTask` exactly 1; `hasOutcome` exactly 1; optional `partOfSession`.
- `Answer`: `status`, `conclusion` required.
- `Claim`: `claimText`, `claimStatus` required; references must resolve.
- `Evidence`: `sourceKind`, `sourceRef`, `supportsClaim` required; references resolve.
- `Artifact`: `sha256` is exactly 64 lowercase hex.
- `SquadMember`: status must be one of the known values; `spawnedBy` optional until P1.
- No duplicate `@id`; no dangling `@id` references for core relations.
- Validation returns errors, never panics; CLI exits non-zero on `ok=false`.

## 7. Acceptance

- `cargo check` / `cargo test --lib ontology` green.
- Same input → same bytes and SHA-256.
- v1/v2 session, old journal, malformed JSONL handled without panic.
- Export contains no key/prompt/tool content; redaction test.
- `1agent ontology export --session <id> --format jsonld` writes JSON-LD.
- `1agent ontology validate --session <id>` reports checks; exit 0 only if ok.
- At least 10 CQs answerable from export (CQ1–CQ4, CQ7–CQ9, CQ11, CQ13–CQ15).

## 8. Parallel workflow

1. Contract freeze (this file).
2. A/B/C work in parallel; each runs its own scoped tests.
3. Lead merges A+B, then CLI; C independently.
4. QA agent writes/executes golden/compatibility/privacy tests and does a read-only review.
5. Lead runs `fmt`, `clippy`, `cargo test`, `verify.sh`; only then continue.

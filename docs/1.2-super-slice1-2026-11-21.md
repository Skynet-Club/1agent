## What shipped

1. **Task profile**
   - `fast` / `standard` / `deep` from objective, deliverable, constraints and
     success criteria.
   - Page-shaped multi-tool tasks (`lark-cli`, URL + skill, `深度思考`,
     `验收`/`质检`) classify as `deep`, not `fast`.
   - Stable prefix guidance; profile-specific checkpoints: fast 12/20,
     standard 30/40, deep 50/65.
2. **Environment manifest**
   - One stable system message with workspace, OS/arch, shell, git root,
     available commands and permissions. `ONEAGENT_ENV_MANIFEST=0` disables.
3. **Step metrics**
   - `StepModelMetrics`: step, profile, provider/model, turn kind, prep/model
     time, TTFT, input/output/cache tokens, cost, context total and
     system/user/assistant/tool/tool-schema split.
   - `StepToolMetrics`: tool calls, tool time, groups, ok/failed/denied,
     cache hits, circuit opens.
   - TUI shows `模型 … · 工具 …` next to tokens/cache.
4. **Cache-safe efficiency and goal recitation**
   - Efficiency nudges are tail-only; the system prefix is not mutated.
   - Goal/constraints/acceptance recitation at profile checkpoints.
   - Compaction boundary recitation: re-check pointers before acting.
5. **Tool governance**
   - Per-run cache for identical side-effect-free calls.
   - Writes clear the cache.
   - Repeated identical failures: cached failure once, then `circuit_open`.
   - `skill_search`, `skill_list`, `memory_recall`, `memory_why`,
     `session_search` are parallel-safe.
   - Tool content over 32k chars is written to
     `<journal-dir>/tool-results/<tool>-<sha16>.txt` and replaced by a receipt.
6. **Page delivery**
   - Page checklist: write → preview → browser open → audit at 390/768/1440 →
     fix and re-audit → acceptance gate.
   - Failed browser audit adds a repair checkpoint.
   - A write after a passing audit adds an audit-recheck checkpoint.
   - Page tasks without an acceptance receipt get an acceptance re-plan.
   - Verification tools may exceed the tool budget by 3 calls.
   - A budget checkpoint tells the model to spend the last calls on
     verification, not another edit.
7. **CLI fix**
   - `1agent run` derives `max_provider_attempts` from `max_steps` when not
     supplied. The old default 8 silently capped 20-step runs at 8 successful
     model calls.
8. **Deep-task notes**
   - Deep guidance asks for a `NOTES.md` with goal, constraints, decisions,
     artifact paths/SHA, failures, open questions and next step.

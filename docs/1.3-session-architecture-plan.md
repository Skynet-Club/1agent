# 1.3 — durable session architecture (2026-11-21)

Status: **Phase 0 and the Phase 1 session MVP landed (2026-11-21)**. Not a
release; version remains `1.0.0-rc.13`.

## Why

Two same-task runs and one failed follow-up exposed the same gap from different
angles:

- 2026-11-20: 59 model calls / 68 tool calls / 365s.
- 2026-11-21: 66 model calls / 81 tool calls / 439s; same final status
  (`conditional`).
- Every model call carried **5,880 system + 6,034 tool-schema tokens = 11,914
  fixed tokens**, and advertised **38 tools**.
- The follow-up “不要带有任何静态文件，都写入一个html当中” died before the
  first model call: `infer_mode` saw “写入” → `CognitiveMode::Execute` →
  `risk_for_mode = High`; the only provider (`deepseek`) has `max_risk =
  Medium`, so the route plan had no candidate.
- The build run that actually wrote files was labelled `DirectAnswer` / `Low`
  risk, because its wording did not contain an execute keyword. Risk followed
  wording, not permissions or actions.

P0 (work ledger + Answer/Ask/Act) fixed a different problem: provenance
questions. It does not make Act tasks faster and it does not provide
conversation continuity.

## Reference designs

| System | Session model | What to take |
|---|---|---|
| Pi 1.5.2 | JSONL tree; active branch → context projection; compaction entries with `firstKeptEntryId`; steering vs follow-up queue; plain-text final | session tree, projection, steering, compaction |
| opencode 2.3.2 | SQLite session DB; message parts (`reasoning`/`text`/`tool`); instruction deltas; hidden compaction/summary/title agents; synthetic resume message; idle outcomes; persisted permissions | reasoning as a part, instruction deltas, helper agents, resume |
| grok shell | 103-line streaming chat, 0 tools, ~1s | latency baseline only; not a task baseline |

## Target architecture

```
run journal (per run, audit)  ── append ──▶  session tree (per conversation)
                                                   │
                                      context projection (active branch)
                                                   │
                                      model call → tool loop → next turn
```

- The run journal stays the audit record. The session tree is the durable
  conversation state and the source of model context.
- A follow-up is a new message on the same session branch, not a new run with
  profile/preflight/route/gates.
- Reasoning is a first-class, streamed part.
- Instructions are deltas (`core/instructions`, `core/date`, `core/skills`,
  `core/mcp`), not a 5.8k block re-sent every call.
- Compaction, summary and title run as hidden helper agents. The main loop only
  reasons and calls tools.
- Delivery tasks keep acceptance, evidence and the work ledger. Chat/answer
  tasks get a thin path.

  - Answer / Ask → Low;
  - Act + `allow_write` → High;

- Use it for `RouteRequest.risk` instead of `risk_for_mode(CognitiveMode)`.
- `NoRoute` names the requested risk and every rejected candidate, e.g.
  `requested risk high; rejected deepseek/deepseek-flash: RiskExceeded`.
- Next-action text points at `providers[].max_risk` in `~/.1a/config.json`.
- Raise the local provider `max_risk` to `high` (with a config backup) so the
  approved full-local workflow can route Execute tasks.
- Tests: risk mapping; fmt/clippy/lib; a live Execute-mode run starts.

### Phase 1 — session MVP

- `src/session.rs`: JSONL session store with session header, message parts
  (user / assistant / tool / reasoning), instruction deltas, compaction,
  synthetic notices, idle outcome.
- `AgentRuntime` loads context from the active session branch at run start and
  appends the run's messages at the end. The per-run journal is still written.
- CLI/TUI: continue the active session (`--continue-session` / session id);
  follow-ups append; only a new Act task runs task profile + capability
  preflight + route planning.
- Synthetic resume message after a process restart: continue without repeating
  completed work.
- Tests: build→question, build→modify, build→new version in one session; assert
  one route plan, no capability preflight on follow-ups, old artifact unchanged
  or edited as expected.

**MVP landed:** `src/session.rs` stores a JSONL transcript per workspace and
session id (`~/.1a/sessions/<workspace-hash>/<id>.jsonl`,
`ONEAGENT_SESSION_DIR` overrides) with user/assistant messages and synthetic
notices. Context projection keeps the last 20 messages within 24k characters.
`AgentRuntime::with_session_path` loads that context before the current user
message, appends the user turn before the run and the assistant turn after it;
an unanswered last user turn gets a synthetic resume notice on the next run.
The per-run journal is unchanged. CLI: `1agent run --session <id>` and
`--continue-session`. TUI: `1agent tui --session <id>` is explicit;
`1agent tui --continue` picks the newest non-archived TUI session for the
current workspace (sessions without a recorded workspace are a fallback).
The conversation session uses the TuiSession id + workspace.

**Continuation:** a session with prior turns skips capability preflight; only a
new session compiles a capability contract. Act continuations still route,
edit the active artifact, and keep acceptance; Answer continuations keep the
tool mask.

**Already-done gate:** an exact objective repeat of a completed/conditional Act
entry whose recorded artifacts are still present and unchanged returns an Ask
answer before route/model/tools: “这个任务在之前的运行 X 中已经完成，记录的产物
未变：…。要新版本，还是只验收现有产物？” Evidence:
`docs/evidence/already-done-gate-2026-11-21/` — 0 model calls / 0 tools on the
repeat, file byte-identical.

**Verification-only mode:** an explicit verify reply with unchanged active
artifacts skips the page checklist, expects the recorded sha256, skips the
design-contract gap and lets a read-only browser audit keep the receipt. With
an accepted receipt the answer is completed with zero writes; a conditional
receipt (real brief/CTA gap) still stays conditional. Debug and installed live
runs are in the same evidence directory.

**New-version path:** an explicit new-version reply with unchanged active
artifacts computes a `-vN` sibling for each active artifact, injects a
`NEW VERSION` target list, and denies `write_file`/`edit_file` calls to the
active path before execution (`new_version_target`); the model retries at the
versioned path. Evidence: `docs/evidence/new-version-2026-11-22/` — the page
test created `page-v2.html` with the original byte-identical; the installed
note test created `note-v2.txt` and completed with 0 writes to `note.txt`.
`terminal_exec` writes to the active path are not intercepted yet.

Evidence: session round-trip and runtime two-run tests; live CLI first run
“记住：我叫测试” followed by `--continue-session` “我叫什么？” answered “测试”,
with the prior user and assistant turns present in the second model request.
A three-turn page test (build → modify → question) and an installed-binary
repeat are in `docs/evidence/session-followup-2026-11-21/`: build had
preflight=1, modify had preflight=0 and edited `index.html` in place
(`c60e48aa…` → `a2dccec3…`), question made one model call, used no tools, and
left the file untouched. Installed binary build 29s / modify 22s. TUI
`--continue` was driven live: one session directory, transcript grew 2 → 4 → 6
lines (`first` → `second` → `third`), and each later request carried the prior
turn. Gates: lib 1420/0/4, bin 69/0, fmt + strict clippy, eval 8/8. Installed
binary sha256 `11a41ff5…`; backup `1agent-pre-core-tools-2026-11-22`
(`7d4c2b85…`).

Deferred to the next slice: steering queue, tool/reasoning parts in the
transcript, compaction entries, TUI known-facts/session duplication, and live
TUI acceptance. Exit: follow-up path has no new route gate; N=3 metrics
recorded.

### Phase 2 — context economics

- Instruction deltas + instruction state; system prompt built from base +
  deltas.
- Reasoning part streamed in the TUI and stored in the session.
- Default tool surface 6–8; the rest via `request_tools`. Target: system + tool
  schema under 4k tokens.
- Hidden compaction/summary/title agents; the main loop never generates a
  summary.

**Core tool surface landed:** the TUI advertises 16 tools (14 core + virtual
`describe_self`/`request_tools`) instead of 38. Live measurement on the same
installed binary: tool schema 6,034 → 3,099 tokens; fixed system+schema
11,914 → 8,267; first context 12,287 → 8,487. Excluded tools return through
`request_tools` (tested with `web_search`). Evidence:
`docs/evidence/core-tools-2026-11-22/`.

**Instruction deltas landed:** `agent_system_prompt_for_run` composes
`AGENT_PROMPT_CORE` with five optional blocks: artifacts (when write/
acceptance tools are advertised), capability (when the capability tools are
advertised), page (artifacts plus the existing page detector), followup
(session or known-fact context), and answer_style (Answer/Ask only). The full
prompt is kept for provider probes and prompt-contract tests. Live TUI note
run: system 5,168 → 3,862 tokens; tool schema unchanged at 3,099; fixed
system+schema 8,267 → 6,961; context 8,487 → 7,182; completed with an accepted
receipt in 18.7s. Evidence:
`docs/evidence/prompt-deltas-2026-11-22/`. The CLI `run` still advertises the
full surface, so it keeps the capability delta.

**Core 8 landed:** the TUI now advertises 10 tools (8 core + virtual
`describe_self`/`request_tools`): read/write/edit/search, terminal create/exec,
preview and acceptance. `browser`, `clarify`, `verify_artifact`, document and
skill tools are requested back when needed; the page delta says so. Live note
run: tool schema 3,099 → **1,910**, fixed system+schema 6,961 → **5,772**,
first context 7,182 → **5,993**, completed. Live page run: first request had
10 tools and no browser, the model called `request_tools` and got browser,
then ran the viewport audit and acceptance; it stopped `completed` with a
`conditional` answer because the post-fix screenshots matched the pre-fix
sha256 (suspected cache). Evidence: `docs/evidence/core8-2026-11-22/`.

**Compact acceptance schema landed:** the `acceptance_gate` spec now only
states the non-obvious decisions; its detailed rules stay in the artifacts
prompt delta. Property descriptions, `additionalProperties` and `default`
were removed from the JSON schema while types, enums, `required` and
`minItems` remain; serde still validates. Live note run: acceptance spec
746 → **379** tokens, TUI core schema 1,910 → **1,543**, fixed
system+schema 5,772 → **5,407**, context 5,993 → 5,632, completed. The model
filled every field; its first gate call failed on a criterion/result mismatch,
retried and returned `accepted`. Evidence:
`docs/evidence/accept-compact-2026-11-22/`.

**Reasoning part landed:** the OpenAI-compatible stream parser reports
`reasoning_content` through a separate callback; `complete_streaming_with`
keeps other providers on the old path. `AgentRuntime::with_reasoning_sink`
feeds the TUI and appends one `SessionEntry::Reasoning` per step; session
context skips it and a resume notice still sees an unanswered user turn. The
TUI drains the sink every 120ms into one `模型思考 Thinking` row, capped at
8,000 live characters. Live DeepSeek run: 2,247 reasoning characters, partial
text visible at 1s and 3s while still running; the follow-up request contained
the prior question and answer but neither reasoning text. Evidence:
`docs/evidence/reasoning-stream-2026-11-22/`. Non-streaming and CLI runs
without a reasoning sink still ignore reasoning.

**Prompt compaction landed:** the code-block, replay and read-only rules moved
to the Answer/Ask delta; a skills delta appears only when skill tools are
advertised; the old follow-up block split into prompt-library, memory and
follow-up deltas; verbose rules were compressed without deleting any asserted
behavior. Live note run: first system message 3,688 → **3,116** tokens, step-0
system 3,864 → **3,409**, fixed system+schema 5,407 → **4,952**, context
5,632 → **5,201**, completed. Stage A exposed prompt-library facts pulling the
whole follow-up block; Stage B removed that 275-token over-inclusion.
Evidence: `docs/evidence/prompt-compact-2026-11-22/`.

**Compaction, steering and Core 7 landed:** sessions above 20 context entries
or 24k characters get a deterministic extractive summary and keep the last 10
entries; the run projects `first_kept_index` so the kept tail survives.
`/steer <text>` during a run injects a user message at the next model step;
plain Enter remains the follow-up queue, and unconsumed steering is requeued.
The TUI now advertises 7 tools (5 core + virtual): read/write, terminal
create/exec and acceptance; edit, search, preview, browser, clarify and the
rest are request-only. Live: core-7 note system 3,234, schema 1,113, fixed
4,347, context 4,569, completed in 15s. A page run requested preview/browser,
received a mid-run steering message and put `STEERLIVE` in the page (19 model
calls, 123s, completed). Evidence:
`docs/evidence/compaction-steer-core7-2026-11-22/`.

Exit: fixed per-call overhead measured and reduced; no 38-tool advertisement.
The original system+schema <4k target is still open: fixed is 4,347, with the
3.2k step-0 system and 1.1k tool schema as the remaining parts.

### Phase 3 — delivery quality

- Ledger freshness for `terminal_exec`-generated artifacts: files named by a
  receipt/answer whose mtime is after run start are recorded as fresh, not
  reused.
- Acceptance contract template includes mobile tap-target and brief-completeness
  checks, or accepts browser-audit evidence for them.
- Fast answer path: one streaming completion, no tools, no structured answer;
  target under 3s.
- Answer starts with the artifact path; auxiliary files are labelled as scratch.
- Optional TUI session-end rating: one line, `1` bad / `2` fine / `3` good /
  `0` dismiss, local only in `~/.1a/session-ratings.jsonl`, skipped when stdin
  is not a TTY. **Landed 2026-11-21**; verified by driving the installed TUI
  through tmux (`/quit` → `3` → `rating: good`).

### Phase 4 — measurement

- Arms: full 1agent, minimal Act, Pi; same task, same model, same endpoint
  (`127.0.0.1:8787`); N=3.
- Metrics: model calls, wall time, TTFT, fixed tokens, tool calls, completion,
  user corrections.
- Feature flags and rollback; no big-bang rewrite.

## Non-goals

- Do not remove acceptance/evidence/ledger for delivery tasks.
- Do not copy opencode's no-audit model.
- Do not add more keyword gates.
- Do not move to SQLite/event sourcing unless JSONL proves insufficient.

## Risks

- `max_risk = high` lets Execute tasks route to the remote DeepSeek endpoint.
  This is a user-approved security decision.
- A session layer duplicates the journal; keep the journal as the audit source
  and the session as the context projection.
- Compaction summaries can drop detail; retain raw journal entries.

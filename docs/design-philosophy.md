
# 设计哲学

[简体中文](design-philosophy.md) · [English](design-philosophy.en.md)

> 先问一句，再动手。  
> 先把事情说清楚，再把它做出来；做完之后，还要能证明为什么算完成。

1Agent 的设计不是从“多接几个工具”开始，而是从几个不变量开始。

## 1. 先问目的，再选手段

用户说“我要一个电钻”，不一定真的需要电钻。  
他可能要在墙上挂一幅画，也可能要穿一根线。不同的目的，正确的方案可能完全不同。

1Agent 把“需求回归”做成一等能力：

- 先判断这是**目标**还是**手段**；
- 如果目的不明确，只问一个能改变方案的问题；
- 给出替代方案时，说明它为什么更接近目的；
- 最终决定由人做出，不由模型替人决定。

这也是产品名的来源：First Principles，不是“先给答案”，而是“先确认问题”。

## 2. 证据是产品原语，不是日志附件

很多 Agent 在最后说“已完成”。1Agent 要求回答：

- 做了什么？
- 依据是什么？
- 哪一步产生了副作用？
- 结果如何被验证？
- 如果重放，能否得到同一结论？

因此：

- 每次运行都有 append-only journal；
- 工具调用和工具结果必须配对；
- 完成声明必须能回到 journal、Artifact 或 receipt；
- `exit code 0` 不等于 `verified`；
- 没有证据的“完成”不成立。

## 3. 人是授权者，不是旁观者

1Agent 的默认姿态是**只读**。

- 读文件、搜索工作区可以默认进行；
- 写文件、执行命令、访问网络需要显式授权；
- 不可逆动作需要逐次确认；
- DelegationProfile 只决定“工作方式”，不授予超过 Authority 的权限；
- 子 Agent 或 Worker 不能自批、不能扩权、不能修改 Authority/Policy/Persona。

这不是为了增加摩擦，而是为了让“委托”这件事成立：  
只有边界清楚，用户才敢把事情交出去。

## 4. 本地优先，数据可带走

1Agent 的核心运行不依赖云端账户：

- 单一 runtime home：`$ONEAGENT_HOME` 或 `$HOME/.1a`；
- 记忆、journal、技能、Goal/Commitment 存在本地；
- 导出包有 SHA-256 清单，默认不包含密钥材料；
- 恢复、升级、回滚、卸载都有明确路径；
- 密钥与配置分离，凭据通过环境变量或本地密钥文件引用。

本地优先不是“拒绝云”，而是“用户可以决定数据去哪里”。

## 5. Provider 中立，路由可见

1Agent 不把某个模型供应商写进领域核心。

- 确定性 provider 用于离线测试；
- OpenAI-compatible adapter 用于 DeepSeek、Kimi、Qwen、Ollama 等端点；
- 路由按能力、风险、成本、延迟和数据边界过滤；
- 每次运行可以说明实际使用了哪个 provider/model、为什么被拒绝、成本是多少。

模型可以换，行为和证据不能换一套。

## 6. 一个 Agent 主体，多个执行者

1Agent 对外只有一个声音。

- Router/协调者负责理解、分派和最终回答；
- Worker 在隔离上下文中执行，不直接对用户说话；
- 执行可以交给 Workshop 的 Session/沙箱/租约；
- 审计记录父任务、子任务、Worker 和 Artifact 的关系；
- “多 Agent”不是拉一个群，而是有所有权、预算、终止条件和验收者的结构。

## 7. 可逆优先

1Agent 偏好可回滚的设计：

- 记忆分 Soft Forget / Hard Forget；
- 技能有版本、评测、canary、rollback；
- 进化提案有证据、审批、应用、回滚和 Ledger；
- 审批有一次性、常设、撤销和过期；
- 发布包有可复现构建和 release manifest。

不可逆动作不是不能做，而是必须逐次确认、留痕，并明确“批准不等于可撤销”。

## 8. 简单优先，结论先行

1Agent 的回答契约强调：

- 先给结论，再给证据；
- 只保留影响决策的信息；
- 区分事实、假设、未知、冲突和翻转条件；
- 不把“分析得很长”当成“分析得很好”；
- 不用模型自述替代可验证结果。

## 9. 开源，但不夸大

1Agent 以 MIT 许可证开源。  
开源意味着可以检查、可以替换、可以自己运行；也意味着我们必须把边界写清楚：

- 当前是 R1 release candidate，不是生产稳定版；
- Linux x86_64 是当前验证平台；
- 浏览器、通用子 Agent、完整常驻 daemon、Bot 仍未完成；
- 没有第三方审计前，不声称“组织级安全认证”；
- 没有真实长周期任务前，不声称“完全自主”。

## 10. 这些取舍意味着什么

| 选择 | 收益 | 代价 |
|---|---|---|
| 证据优先 | 可解释、可回放、可审计 | 记录更多、实现更重 |
| 默认只读 | 降低误操作和越权风险 | 首次使用需要配置授权 |
| Provider 中立 | 不被单一模型锁定 | 路由和评测更复杂 |
| 本地优先 | 数据可控、可迁移 | 云同步/多端体验需要额外建设 |
| 一个有界主体 | 行为稳定、责任清楚 | 多 Agent 吞吐需要更复杂的调度 |
| 可逆优先 | 出错可回滚 | 需要版本、评测和 Ledger |

这些代价是刻意接受的。  
1Agent 的目标不是“看起来最像人”，而是“值得把一件重要的事交给它”。

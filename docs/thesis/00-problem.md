# 问题定义：1-Agent 的命题

Date: 2026-11-04
Status: proposed; not implemented; not evaluated

## 1. 命题

1-Agent 在回答之前，判断"这个请求是不是达成目的的手段"；只有当停止规则满足且有
证据时，才提议更优手段；否则按原请求执行。

反例（本命题不适用于）：已是字面请求、约束不可变、无可交付替代、或问题属于
complex 域（原因只能事后得知）。

## 2. 术语分层

当前 `TaskRequest` 把下列五个概念压进一个 `objective: String`。这是结构性缺陷，
不是命名问题。

| 层 | 定义 | 谁拥有 | 可否质疑 |
|---|---|---|---|
| request | 用户原话 | 用户 | 不可变 |
| need | 用户可验证的目的 | 用户 | 可由 1A 提议，用户裁决 |
| requirement | 世界应满足的状态 | 用户 + 1A | 需证据 |
| specification | 系统应执行的动作 | 1A | 可被推翻 |
| domain assumption | 被当作既定的世界事实 | 未声明 | **必须可证伪** |

Zave & Jackson (1997) 的划分：requirement 描述世界，specification 描述机器。
钻头故事的失败几乎全部发生在 domain assumption（墙可钻、房东允许、有电源、
信号可达），而不是发生在需求层级不够深。

## 3. 停止规则

继续向上回溯，当且仅当下一层同时满足：

1. **可验证**：用户自己能判断真假。
2. **可交付**：1A 或下游具备交付该层替代手段的能力。
3. **存在更优替代**：该层上存在成本/风险/时间显著更优的手段。

任一条件在下一层失效，即停在当前层。

链长约束：默认 1 跳；2 跳需额外证据；3 跳以上视为哲学化，拒绝执行。

依据：Keeney, *Value-Focused Thinking* (1992) 的 fundamental objectives hierarchy —
手段目标与目的目标的分界，正是"能否再向上问一层且仍有意义"。
对照反例：无限回溯会产生"人为什么要上网 → 为了不孤独 → 建议心理咨询"这类
不可验证、不可交付的结论。

## 4. 三条不变量

1. **原请求不可变**：`stated_request` 与 `chosen_level` 分离存储；重构失败时用户
   可退回原路。
2. **重构是提议，不是执行**：默认只提议；涉及花费、不可逆、或跨越权限边界的
   替代必须显式确认。
3. **每跳必须可反证**：每一跳同时给出 domain assumption、被否决的替代、以及
   "在什么情况下这个重构是错的"。

## 5. 默认不重构

必须先做 means/end 分类，**默认判为 end**。理由：

- 绝大多数请求是字面请求，误重构的代价（信任损伤 + 范围膨胀）高于不重构；
- 无证据的重构等同于误导；
- 用户不会每次都纠正你，静默错误会累积。

升级为 means 需要三项同时成立：目标与手段不匹配、替代方案可交付、成本显著更优。

## 6. 失败模式 → 契约字段映射

每个失败模式必须有对应字段承载，否则只是口头警告。

| 失败模式 | 承载字段 | 机器可检形式 |
|---|---|---|
| 过度回溯 | `hops[].stop_rule_passed` | 链长上限 + 每跳三条件布尔值 |
| 替代方案幻觉 | `substitute.preconditions` | 用原始 constraints 复核，不复用简化世界 |
| 隐性成本转移 | `substitute.new_costs`（必填） | 非空校验；只报收益即失败 |
| 迎合式重构 | `hops[].falsifier`（必填） | 与 `rejected_alternative` 成对出现 |
| 决策权篡夺 | `decision_gate` | `stated_request` 不可变；未确认不得执行 |
| 不可审计 | journal 事件 | 整链可 replay、可 audit |
| 销售式引导 | `counter_argument`（必填） | 必须同时陈述"原方案仍然成立"的理由 |

## 7. 什么会证伪整个命题

以下任一成立，则本命题不成立，应停止扩展而非继续调参：

1. 对照实验中，regress-then-solve 的用户接受率不显著高于直接执行；
2. `regret_rate` 高于 `obviation_rate`；
3. 抽取的"更高层需求"无法由用户自己验证（可验证率低于阈值）；
4. 替代方案在原始约束下复核失败率过高（说明是幻觉而非推理）；
5. 在真实语料中 means 类请求占比过低，产品价值不成立。

第 5 条需要先测量。当前 `.journal` 75 条真实 run 中，真实用户请求约 10 条，
无一触发目标质疑；因此本命题的语料基础必须外部采集，不能自证。

## 0. 一页结论

### 0.1 0.98.2 的定位

0.98 证明的是“Agent 能在真实世界里执行，且每一步可授权、可接管、可回滚、可验收”。  
0.98.2 要证明的是：

> **执行留下的每一个结论、证据、动作、队员和产物，都能被稳定地解释、查询和追溯。**

主题：**Semantic Lineage**。  
方式：**运营型本体类型注册表 + 数据绑定 + 只读导出/校验 + 血缘字段 + 查询/UI**。  
原则：**journal 仍是唯一事实源；本体是可重建投影；不把推理机放进运行时。**

### 0.2 必须交付

1. **Type Registry**：Object/Property/Link/Action/Function/Interface/Value 类型，版本化。
2. **Data Binding**：类型/属性 → journal/session/registry 字段，带 `mappingVersion`。
3. **只读导出**：`1agent ontology export` 生成确定性 JSON-LD/PROV；支持 session 和单 run。
4. **校验**：`1agent ontology validate` + SHACL/内部规则；报告不阻塞运行。
5. **血缘**：队员 parent session/run/spawn call；会话 fork；action log run/session；读文件 SHA；policy/approval metadata。
6. **动作与安全**：ActionType、ActionInvocation、PolicyDecision、Approval、AccessPolicy/Purpose 的导出映射。
7. **身份与时间**：稳定 IRI、artifact SHA 身份、alias/merge 溯源、`observedAt/recordedAt/validFrom/validTo`。
8. **查询 CLI**：SQLite 投影 + 16 个 CQ 查询；TUI 血缘/证据完整度为 Should（可移 0.98.3）。
9. **文档/证据/发布**：0.98.2 证据包、兼容性报告、owner 审批。
10. **Quality & Latency 并行工作流（Track Q，建议交付）**：基线、失败归因、路由/上下文/并行只读/分层验证实验；独立 QG 门禁，不与语义门混报；2 人时先 QG0/QG1。

### 0.3 明确不做（0.98.2）

- 不启动 OWL 2 DL reasoner，不引入三元组数据库作为运行时依赖。
- 不迁移 journal 主存储，不双写本体库。
- 不要求模型输出新的必填字段，不改 AgentAnswer schema v2。
- 不做 A2A、OpenTelemetry、跨组织 Agent 交换（0.99/1.0）。
- 不做完整 Commitment/Delegation 生命周期（0.99）。
- 不做 LLM 自动本体抽取/自动映射入库。
- 不把 PID、标题、路径当实体身份。
- 不做模型微调/训练；不把本体/验证/检索无差别塞进每轮 prompt。
- 不使用未经 A/B 的 prompt 堆叠；每个实验必须可回滚。

### 0.4 五条硬不变量

1. **journal 是事实源**；本体导出失败不影响运行，可从 journal 重建。
2. **密钥、原始 prompt、完整文件内容不进本体导出**；只保留引用、哈希、必要摘要。
3. **没有校准记录就不输出置信度数字**；保留 claimStatus，不伪造概率。
4. **不可逆动作必须可追溯**：ActionType、PolicyDecision、Approval 至少有一个明确关联，否则标 `Unknown`。
5. **不把未验证写成通过**；门禁未过则延期，不因日期缩范围。

## 1. 需求

### 1.1 用户与场景

| 用户 | 场景 | 现在的问题 |
|---|---|---|
| 运维/审计 | “这条结论依赖哪些证据？谁批准了这次点击？” | 需要手写脚本遍历 journal/session/action log |
| 开发者 | 新增字段/事件后，导出和查询不漂移 | 没有类型注册表和绑定校验 |
| 安全/合规 | 导出不能泄露密钥/原始 prompt；权限要随导出 | 没有 permission-aware export |
| Super-Agent 设计者 | 队员、父任务、承诺、产物要可追溯 | SubagentRecord 缺 parent session/run/spawn call |
| 外部消费者 | 用 JSON-LD/PROV 消费 1Agent 数据 | 没有稳定 IRI、没有 PROV 映射 |

### 1.2 需求列表

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| R1 | 类型注册表：Object/Property/Link/Action/Function/Interface/Value | Must | 每个核心类型有定义、版本、owner |
| R2 | 数据绑定：类型/属性 → 具体字段，带 mappingVersion | Must | 核心类型/属性 100% 有绑定或显式 `Unknown` |

| R7 | 身份与时间：稳定 IRI、SHA、alias/merge、bitemporal | Must | 0 PID IRI；同 artifact 同 SHA；时间字段可重建 |
| R8 | 查询/UI：SQLite CQ 查询（Must）；TUI 血缘/完整度（Should） | Must / Should | 16/16 CQ 可回答；TUI 不泄露敏感内容 |
| R9 | 文档、证据、兼容性、发布 | Must | verify + 证据包 + owner 审批 |

### 1.3 Competency questions（16）

沿用 [`super-agent-ontology.md`](super-agent-ontology.md) 的 CQ1–CQ16：

- CQ1–CQ4：claim/evidence/artifact/队员血缘
- CQ5–CQ8：授权、审批、conditional、证据过期
- CQ9–CQ12：checkpoint/replay、session fork、eval 映射、审批后 SHA 漂移
- CQ13–CQ16：队员失败、provider/route/cost、audit/replay、不可逆动作

0.98.2 的 G1 至少 10/16（核心证据/运行/成本/审计），G2 补齐血缘/动作类 CQ，G3 要求 16/16 或明确记录不可回答项。

### 1.4 非目标

见 §0.3。特别强调：**不把“有了 JSON-LD”当成“语义层完成”**；没有绑定、
动作、安全和血缘的导出，只是文档。

## 2. 功能描述

### F1. 类型注册表（Type Registry）

**做什么**

- 定义 `ObjectType`、`PropertyType`、`LinkType`、`ActionType`、`FunctionType`、
  `InterfaceType`、`ValueType`。
- 每个类型带：`id`、`version`、`owner`、`source`、`cardinality`、`required`、
  `description`、`deprecated`。
- 注册表是 JSON（机器可读）；JSON-LD/OWL/SHACL 从注册表生成或校验。

**输入/输出**

- 输入：`ontology/types.json`（或分模块文件）。
- 输出：`1agent ontology types --json`、生成的 JSON-LD context/SHACL。

**验收**

- 所有 0.98 核心实体有类型：Session、Run、Task、ToolInvocation、Observation、
  Answer、Claim、Evidence、Artifact、SquadMember、ActionType、DataBinding 等。
- 类型版本变更必须显式；破坏性变更需 `deprecated`/迁移说明。

### F2. 数据绑定（Data Binding）

**做什么**

- 每个对象/属性映射到 journal 事件字段、session.json 字段或 registry 字段。
- 每条绑定：`type`、`property`、`sourcePath`、`mappingVersion`、`required`、
  `transform`、`owner`。
- 绑定校验：源路径存在、类型匹配、必填项有绑定、mappingVersion 单调。

**验收**

- 核心类型/属性 100% 有绑定或显式 `Unknown`。
- 修改字段但忘记改绑定，`ontology validate` 失败。
- 绑定覆盖率报告进入证据包。

### F3. 只读导出（Export）

**命令**

```bash
1agent ontology export --session <id> --format jsonld --out <path>
1agent ontology export --session <id> --format ttl
1agent ontology export --journal <path> --format jsonld
```

**要求**

- 读取 session.json + journals；不改 runtime，不联网。
- 稳定 IRI（§4.2）；确定性序列化；输出 SHA-256。
- 默认不导出原始 prompt、工具全文、密钥；只导出引用/哈希/摘要。
- 单 run 导出允许没有 session link；session 导出必须有 `partOfSession`。

**验收**

- 同一输入重复导出字节一致。
- v1/v2 session、旧 journal、坏 JSONL 不 panic。
- 导出文件不含密钥/原始 prompt；redaction 测试通过。

### F4. 校验（Validate）

**命令**

```bash
1agent ontology validate --session <id> --format text|json
```

**规则**

- 内部规则：必填、枚举、IRI/时间格式、claim/evidence 引用完整性、
  artifact SHA 格式、run outcome、squad parent。
- SHACL：P0 接内部校验；P1 接 `pyshacl`/Jena 或 Rust SHACL 库，作为发布证据。
- 校验失败只报告，不阻塞运行。

**验收**

- 能发现：claim 无 evidence、evidence 指向不存在 claim、run 无 outcome、
  squad 无 parent、artifact SHA 非法。
- 对当前真实 session 的已知例外有清单，不静默忽略。

### F5. 血缘（Lineage）

**改动**

| 数据 | 新字段/关系 |
|---|---|
| `SubagentRecord` | `parent_session_id`、`parent_run_id`、`spawn_call_id`、`child_run_id`（可选） |
| `SessionRecord` | `forked_from_session_id`（可选） |
| `ActionLogEntry` | `run_id`、`session_id`、`action_type`（可选） |
| `ToolObservation.metadata` | `policy_outcome`、`policy_reason`、`authority_profile_id`、`approval_card_id` |
| `read_file`/`search_files` | `sha256`（内容可读时） |

**兼容**

- 全部 `#[serde(default)]` / 可选 metadata；旧记录缺失为 `None`。
- 不新增 journal 事件；session↔run 继续由 session.json 的 journals 列表 join。

**验收**

- 新子进程记录 100% 有 parent session/run/spawn call。
- 旧 registry/session 可读；缺失字段导出为 `Unknown`，不伪造。
- TUI Agent-分队显示 parent 链接；会话选择器显示 fork 关系（P2）。

### F6. 动作与安全（Action / Security）

**做什么**

- 从 `CuaAction`/`ActionCard` 生成 `ActionType`：风险、可逆性、权限、descriptor。
- `ActionInvocation` 关联 `ToolInvocation`、`PolicyDecision`、`Approval`、`Purpose`。
- `AccessPolicy` 先映射现有 `AuthorityProfile`/`PermissionSet`；不新建第二套权限源。
- 导出是 permission-aware：无权限的字段/对象按策略脱敏或省略。

**验收**

- 不可逆动作 100% 有 ActionType；有 policy/approval 就关联，没有标 `Unknown`。
- 导出不泄露 secret、原始页面内容、审批人密钥。
- ActionCard/Approval 的现有测试仍通过。

### F7. 身份与时间（Identity / Time）

**规则**

- 实例 IRI 按 [`super-agent-ontology.md`](super-agent-ontology.md) §4.2。
- Artifact 以 SHA-256 为主身份；路径是属性。
- `EntityAlias`/`mergedInto` 带 provenance；PID 只作 `processId` 观测。
- 时间四元：`observedAt`、`recordedAt`、`validFrom`、`validTo`；能取到才输出。
- `ConfidenceAssertion` 只在有校准记录时输出；否则省略。

**验收**

- 0 个 PID 进入身份 IRI。
- 同一 artifact 不同路径导出同一 SHA IRI。
- 时间字段可从 journal/证据重建；缺失不默认 now。

### F8. 查询与 UI

**做什么**

- SQLite 投影：`entities`、`relations`、`bindings`、`cq_results`。
- `1agent ontology query --session <id> --cq CQ1` 返回结构化结果。
- TUI：
  - 会话选择器预览显示“证据完整度/最近 claim”（不泄露原文）；
  - Agent-分队详情显示 parent session/run/spawn call；可打开子 journal。
- 不把 SQLite 设为运行时依赖；按需构建/更新。

**验收**

- 16/16 CQ 可回答（或明确记录不可回答）。
- 查询延迟：单 session < 500ms（本地投影）；导出单 session < 2s 典型。
- TUI 在 80×24 和 100×32 不溢出、不泄露敏感内容。

### F9. 文档、证据、发布

- 更新 `docs/super-agent-ontology.md`、`ontology/*`、`docs/tui.md`、feature matrix。
- 证据目录：`docs/evidence/0.98.2-ontology/`。
- 兼容性矩阵：v1/v2 session、旧/新 journal、旧/新 registry。
- 发布说明明确“本体是只读投影，不是运行时事实源”。

## 3. 架构与数据流

```text
journal + session.json + subagent_registry + action_log
                    │
                    │  (read-only, deterministic)
                    ▼
          Type Registry + Data Binding
                    │
       ┌────────────┼─────────────┐
       ▼            ▼             ▼
  JSON-LD/PROV   SHACL/内部校验   SQLite/GraphQL 投影
       │            │             │
       ▼            ▼             ▼
  外部交换/审计   发布门禁       CQ 查询/TUI
```

原则：

- 只有最左侧是事实源；右侧全部可重建。
- 类型/绑定是“模型只写一次”的源；JSON-LD/SQL/GraphQL 是投影。
- 运行时不依赖右侧任何组件；导出失败只影响导出。

## 9. 与 1.0 / Super-Agent 的关系

0.98.2 不是 Super-Agent 全部，但它是地基：

- Super-Agent 需要跨会话、跨队员、跨机器的稳定身份与承诺；0.98.2 先补 stable IRI、parent lineage、action/security。
- 0.99 再做 `Commitment/Delegation`、A2A、OTel、持久队员。
- 1.0 的审计/合规/外部互操作必须能回答“谁、何时、凭什么、做了什么、产物是什么”；0.98.2 先让这些问题在单机可回答。

### 9.1 距离 Super-Agent 还有多远

| 能力 | 当前 0.98 | 0.98.2 后 | 0.99 | 1.0 Super-Agent |
|---|---|---|---|---|
| 目标闭环 | 一次 TaskRequest 跑完 | Goal/Commitment 只读投影 | GoalKernel 驱动调度/承诺/验收 | 长期、多目标、跨会话自治 |
| 执行内核 | run-centric | 不变 | ActionRuntime + 授权/用途 | 组织级执行 |
| 委派 | spawn_agent 子进程 | 补 parent lineage | Delegation/Commitment 生命周期 | 持久队员、接管、团队 |
| 信任 | journal/audit | JSON-LD/PROV/CQ/一屏审计 | 动作/政策/用途关联 | 外部审计、SDK/API |
| 学习 | eval/skill 初步 | Track Q 基线/路由实验 | 失败归因闭环 | 组织级学习/生态 |
| 互操作 | 自定义 JSON | JSON-LD/PROV | A2A/OTel 投影 | 跨组织 Agent 网络 |

**结论**：0.98.2 是语义与信任地基，不是 Super-Agent 内核。0.99 才补：

1. `GoalKernel`：Goal/Intent/Commitment 生命周期驱动运行；Outcome/Metric 与 Answer 分离。
2. `ActionRuntime`：ActionType、风险/可逆性、Authority、Purpose、Approval 进入执行路径。
3. `DelegationKernel`：子 Agent 作为带 Goal/Commitment/验收的委派，而不是一次 tool call。

0.98.2 完成后，0.99 内核约 8–12 周（3 人），1.0 还需 12–16 周 + 外部审计；
从当前基线到可信 Super-Agent 约 **6–9 个月**（估算，不是发布日期承诺）。
如果 0.98.2 后继续加本体 UI/更多类型，而不做上述三块内核，距离 Super-Agent 不会缩短。

**如果 0.98.2 只能做一半**：优先 P0（Type Registry + Bindings + Export + Validate），
其次 P1 的 lineage（Subagent parent/Session fork/read SHA），再其次 action/security，
最后 query/UI。若 owner 决定缩范围，必须把 R6 和 R8 的 TUI 部分明确移到 0.98.3 并写入
release notes；查询 CLI 尽量保留。不得默默把 Must 降级。不得为了 UI 牺牲导出确定性/隐私门禁。

## 10. 并行工作流 Q：Quality & Latency

### 10.1 定位与边界

Track Q 与 Semantic Lineage 并行，但**独立计量、独立门禁**：

- 目标：在不牺牲安全/可审计的前提下，提升任务正确率、首答可用率与响应速度。
- 不把本体、检索、验证无差别塞进每轮 prompt；每个实验必须可回滚。
- M1 rerun3 已到 **239/240 = 99.58%**，接近饱和；质量提升主要看 100 题、真实工作流、难例与人工盲评。
- 当前真实 run 中模型耗时占 89%–99%；速度大头在模型选择、步数、上下文、并发与网络，不在 Rust 微优化。
- 不在 0.98.2 做模型微调；不做未经验证的“更大 prompt/更多 critic”。

### 10.5 QG 门禁

- TTFT 或端到端 p95 改善 ≥10%，或明确记录无改善原因。
- M1 ≥97%、100 题不低于基线、replay 100%。

#### QG2 质量提升

- 100 题 ≥96/100；M1 ≥97%；人工盲评无回退。

- 有效配置进入 router/prompt/工具策略；无效实验回滚。
- 成本不超基线 +10%（或 owner 批准）。
- 安全/权限/隐私 0 新增 P0。
- 质量/速度声明有 A/B 证据；未达标写 release notes，不写成通过。

### 10.6 实验协议

- 一次只改一个变量；保留对照组。
- 用 held-out 任务，不在调参集上宣称提升。
- 样本 ≥30/组；报告均值、p50/p95、置信区间或至少原始分布。
- 质量提升必须同时看速度/成本；速度提升必须看质量/安全。
- 任何 prompt/路由变更必须可回滚；保留旧配置与证据。

### 10.7 与 0.98.2 的关系

- Track Q 不改变 0.98.2 的 Semantic 交付定义；两者独立报告。
- Semantic 的 lineage/CQ 可用于 Q 的失败归因，但不能替代 Q 的 A/B。
- 如果 Track Q 未达 QG2，0.98.2 仍可交付 Semantic 核心，但**不得在 release notes 宣称质量/速度提升**。

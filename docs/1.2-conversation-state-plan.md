# 1.2 — conversation state, work ledger and interaction modes (2026-11-21)

Status: **P0 landed and live-verified (2026-11-21)**. Evidence:
`docs/evidence/conversation-state-2026-11-21/README.md`.

## Why

The 2026-11-21 real run asked “你这个是重新设计的，html，还是用昨晚的来对付我呢？”
and the runtime compiled it as a page-build task:

- `TaskProfile`: `deep`, confidence 85, reason “complexity markers: 设计”
- `CapabilityPreflight`: `deliverable=text/html`, `verb=build` (required),
  `verb=preview`; acceptance “artifact exists and is previewable”

The model understood the question and answered correctly in its final JSON, but
the structured answer failed validation and was replaced by the
“答案结构无法修复…本轮没有执行任何外部动作” fallback. The run spent 14 tools
and 1m27s on a provenance question.

Root cause: the runtime has task profiling and capability compilation but no
**conversation state**. It cannot distinguish “build a page” from “did you build
a new page?”, and it has no compact record of what the previous run did.

## Research basis

| Work | Finding | Consequence |
|---|---|---|
| Tack, Laban, Neville, *LLMs Get Lost in Evolving User Intent* (arXiv 2607.20734) | static task performance does not transfer to evolving/redirected intent | maintain explicit active intent, not just the current utterance |
| *When Users Change Their Minds* / IntentFlux (arXiv 2609.32520) | superseded intent contaminates actions; explicit state raises 0.367→0.467 but does not recover single-turn | state is necessary but not sufficient; gate actions too |
| AgentAbstain (NeurIPS 2026, arXiv 2607.10059) | best model 59.5% paired act/abstain accuracy; abstention is independent of task-solving; “post-hoc abstention” | make Answer/Ask/Act an explicit decision before planning |
| When2Call (NAACL 2025) | direct answer / tool call / follow-up / abstain are distinct decisions | same four-way boundary |
| Ask, Answer, or Act (EMNLP 2026) | explicit interaction modes improve clarification, abstention and when-to-call | put the mode in the planner action space |
| Anthropic, *Effective harnesses for long-running agents* (2025) | `claude-progress.txt` + feature list + git log let a fresh session recover; a later agent otherwise “looks around, sees progress, and declares the job done” | append-only work ledger read at session start |
| Anthropic, *Effective context engineering* (2025) | structured note-taking and a file-based memory tool persist state outside the window | ledger is injected, not rediscovered |
| Manus, *Context Engineering for AI Agents* (2025) | file system as external memory; `todo.md` recitation; after a user message the agent must reply before acting | reply-first + hard mask of action tools in Answer mode |
| *How Strongly Should Task State Influence an LLM Agent?* (arXiv 2609.25686) | an agent-written ledger beats a shown checklist; enforcement pays only when failures are state-decidable and frequent, and hurts when the gate is wrong | enforce only decidable rules; do not keyword-gate all intent |
| Recurs (arXiv 2608.24876), DeepAgent (WWW 2026) | working memory tracks progress/unresolved goals; episodic/working/tool memory folding | ledger structure: facts, artifacts, blockers |

## Architecture

```
user input
  → Work Ledger load (runtime facts: artifacts, sha256, fresh/reused, blockers)
  → Interaction Mode Gate: Answer | Ask | Act
      Answer: answer from ledger; no deliverable contract, no page checklist,
              no acceptance gate; write/delivery tools masked; ≤2 tools
      Ask:    one clarification question; no tools
      Act:    existing capability contract + acceptance flow
  → execute
  → Work Ledger append (facts from the journal, not model claims)
```

### P0 — the fix for the observed failure

1. **Work ledger** (`src/work_ledger.rs`)
   - Append-only JSONL under `~/.1a/work-ledger/<workspace-hash>.jsonl`
     (`ONEAGENT_WORK_LEDGER_DIR` overrides the root for tests).
   - Entry: run id, session id, time, objective, interaction mode, status,
     artifacts (`path`, `sha256`, `bytes`, `fresh`), reused paths, blockers.
   - Load the last 5 entries at run start; compute current `size/sha256` for
     referenced artifacts so the model can answer “is this the same file?”.
   - Inject a compact `WORK LEDGER` system message. Facts come from tool
     observations; the model only writes the objective/blocker narrative.
2. **Interaction mode gate** (`src/interaction_mode.rs`)
   - Modes: `Answer`, `Ask`, `Act`.
   - Signals: explicit action verbs, request framing, interrogative markers,
     prior-work references (`昨晚/上次/还是/这版`), explicit new-build wording,
     vague-change wording, ledger presence.
   - Default is `Answer` unless the request is clearly an action; a false
     `Answer` costs one retry, a false `Act` costs a 15-step audit and can
     overwrite an old artifact.
   - Journal `InteractionModeSelected` with mode, confidence and reasons.
3. **Hard mask in Answer mode**
   - Do not run capability preflight.
   - Do not inject the page delivery checklist.
   - Do not create a design completion gate.
   - Remove write tools, `acceptance_gate`, `preview_file`, `verify_artifact`,
     `browser` and `resolve_capability` from advertised and executable tools.
   - Cap tool calls at 2 and steps at 4.
4. **Truth preservation**
   - The unrepairable-answer fallback keeps the model’s plain-language
     conclusion and reports real tool counts; never says “nothing happened”.
5. **Regression**
   - After a build run, the exact user sentence must produce:
     `mode=answer`, 0 capability contracts, 0 acceptance gates, ≤2 tools, a
     direct “same file / reused / no new writes” answer.

### P1 — continuity and correction

6. Active task: resolve “改一下/再来一版” against the last Act artifact.
7. Intent echo: one line at run start (“你是在问…；我先查账本，不重做”).
8. New Act tasks default to a new artifact path (`-v2`); modifications edit the
   active artifact.
9. Paired multi-turn suite: build→question, build→modify, build→vague,
   build→“did you test it?”, build→new version.

### P2 — learned and visible

10. Learn the mode decision from traces (Ask/Answer/Act), not more keywords.
11. TUI badge: `本轮新建 / 沿用旧产物 / 只读核查`.
12. Ledger-backed session handoff for long-running work.

## Non-goals

- No new keyword rules in `compile_contract`; the gate is above it.
- No prompt-only fix: Answer mode must remove the wrong tools and contract.
- No acceptance gate for Answer/Ask.
- No claim that this solves all evolving-intent ambiguity; IntentFlux shows
  explicit state only partially closes the gap.

## Verification

- Unit tests for mode classification (Chinese and English, build/question/
  modify/vague/new-version).
- Runtime integration: build run → follow-up question; assert mode event, no
  capability preflight, no acceptance gate, no writes, ledger context contains
  the artifact sha256.
- Existing gates: `cargo fmt --check`, strict clippy, `cargo test`, eval 8/8.
- Live: the exact user sentence in a workspace containing last night’s
  `index.html`; expect a one-step answer and the old file untouched.

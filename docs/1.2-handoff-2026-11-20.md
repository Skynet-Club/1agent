## Update 2026-11-20 MA-011 process group/registry reconcile

- A root spawn starts the child in its own process group; a depth-0
  cancel/timeout/wait failure/finished child kills the group, so depth-2
  descendants do not survive. Deeper spawns inherit the ancestor group and
  depth 2 is the leaf.
- Linux/Android children set `PR_SET_PDEATHSIG=SIGKILL` in `pre_exec` and
  re-check `getppid`; a parent `SIGKILL` cascades down the spawn tree. Other
  Unix targets skip the kernel feature.
- `subagent_registry::reconcile_stale_records` marks active records `Failed`
  when the child (or starting parent) pid is gone, after a 2-second grace.
  `load_recent_current` reconciles before the UI reads records.
- The idempotency ledger explicitly unlocks in `Drop`; a forked child briefly
  sharing the open file description could otherwise keep the `flock` alive and
  produce a spurious "already in progress".

  from `ONEAGENT_SUBAGENT_TREE_MAX_COST_MICROS` and
  `ONEAGENT_SUBAGENT_TREE_MAX_TOKENS`. Children inherit the file and cannot

## Known limits

- Tree budget undercounts a child that dies before its journal is readable; the
  budget file is an overspend guard for cooperating agents, not a sandbox.
- `1agent run --max-cost-micros` / `--max-tokens` bound only that run; tree-wide
  cost/token limits use the `ONEAGENT_SUBAGENT_TREE_*` environment variables.
- Master compensation is a plan, not execution, and artifact ownership is not
  tracked; the operator must not remove a file the task did not create.
- Subagent child writes are not converted into compensation plans; their
  journals remain the source of truth until pre-write snapshots exist.
- Spawn idempotency caches only completed outcomes; a crash between child
  completion and the record write can still duplicate on retry. Spawns outside
  a `RunContext` are not deduplicated, and cache entries have no TTL.
- PDEATHSIG is Linux/Android only; process-group cleanup is not a sandbox
  (`setsid` can escape). Registry reconciliation runs when the UI loads records,
  not on every CLI run.
- OTel remains a journal projection: `otel-export` takes one journal, so a
  spawn tree is joined in the collector. A top-level run has no journaled
  session id, so its conversation id stays the run id.
- The TUI preview's first read is capped at 256 KiB; one enormous event can
  consume that budget and hide older timeline lines.
- Parallel smoke did not prove same-workspace concurrent writes, DAG ordering
  beyond the smoke, >128 sessions, or compensation paths.

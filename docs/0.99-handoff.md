## 0.0a 跨会话记忆（2026-11-17）

新会话不再只有当前 session 上下文。TUI 在回忆型问题前只读检索其它 session
的标题、用户请求和回答结论，最多 3 条、4000 字符，排除当前 session；全量运行
可调用 `session_search`。无命中时明确说“没有本地记录”。只读、不使用/不返回
工具观测、不改写记忆、不把旧回答升级为已验证事实。设计见 ADR-0146。

实测：隔离 store 中问“昨天我们聊的 F开头和G开头你还有印象吗？”，TUI 回答
“有印象。昨天你问的是…”，复述旗舰/前景/锻造等四类词与 Futuregrid 等代号；
真实 store 的新会话 `ses_efdc03779f164b71b116e6bf5ad799d8` 也通过，journal
的 `known_facts` 保存了注入的记录。最终提交 `b4acd99`，`verify.sh` 绿：
1183 lib tests、1621 total、core-v3 8/8。

边界：词法检索（英文词 + 中文二元组），不是语义向量库；分层 MemoryService
仍是独立策展记忆，不自动写入。

后续 `7609c04` 修复了真实运行暴露的校验问题：模型把“旧会话说没印象”与
“检索到记录”标为 resolved conflict，并把冲突内的获胜 claim 写进
`resolution_claim_ids`；旧校验器拒绝这种重叠，修复调用又拿到同样结构，最终
降级 `needs_evidence`。现在允许该重叠；未知/重复 resolution id 仍失败关闭，
resolution source 仍必须由相关 claim 声明。失败 journal
`fe27edd0-4848-4c39-acb6-791545557e1f` 的两版模型答案均已重新校验通过。
`48f2771` 还让跨会话检索跳过 `answer repair failed` 的失败运行，并要求每个
命中至少带一条运行片段，避免失败问题排在真正回答过它的会话前面。

## 0.0c 提示词补齐窗（2026-11-17）

`//`、`；；`、`;;` 现在都能紧贴正文触发提示词补齐，URL 的 `://` 不误触。
补齐窗改为三栏：左侧类目（加目标 … 原文库，不含“全部”）、中间当前类目
的提示词、右侧选中项的完整详情。窗体与会话框同宽、固定高度，切换时不再
上下窜动。默认焦点在类目，`→` 进列表、`←` 回类目、`↑↓` 选择、`Enter`
应用、`Esc` 关闭并恢复原文，`Tab` 在类目栏等同 `→`、在列表等同 `Enter`。
原文库保留 56 条原文/32 组，重复插入跳过。

PTY 实测：输入 `做个网页//` 后出现三栏，左侧从“加目标”开始，中间显示
“真正的目的是 / 下一步拿它干什么 …”，右侧显示选中提示词的完整正文和
用途/变量/插入/输出来源；`→`、`↓`、`Enter` 后输入框合并“做完这个之后…”

# 1Agent 1.2 — completion reliability plan (2026-11-21)

Status: **next slice; not implemented**.

## Why

The final-binary T1 n=3 (see `docs/evidence/super-2026-11-21/t1-n3.json`) is
fast and audit-clean, but not reliably complete:

| Metric | Result |
|---|---:|
| Median wall clock | 178.1s (baseline 365.0s, 2.05×) |
| Median loop steps | 30 (baseline 59) |
| Final browser audit pass | 3/3 |
| Acceptance gate accepted | 2/3 |
| Completed | **1/3** |
| Final statuses | conditional / completed / conditional |

Two distinct failures:

1. **Accepted receipt, incomplete design contract.** The acceptance receipt
   was accepted, but the page design contract still lacked brief completeness
   and independent design-review evidence. The runtime named both gaps; the
   model did not close them before the run ended.
2. **No acceptance receipt.** The run ended conditional without calling
   acceptance_gate, even though the page audit was clean.

The audit reliability is now good. The remaining problem is **turning a clean
page into an accepted, completed delivery**.

## Hypotheses

- H1: The acceptance contract is drafted too late, so the model discovers
  missing design evidence only after the page is built.
- H2: The model spends its last calls on edits and does not reserve enough for
  acceptance and design review.
- H3: The design review evidence is not actually produced; the model treats
  “I checked the unslop rules” as equivalent to an independent review.
- H4: A read-only critic or a preflight contract check would close the gap
  without more tools or a bigger budget.

## Exploratory result already run (do not repeat the same mistake)

A combined R1+R3 change (contract preflight in the page checklist + verification
reserve 5) was tested on T1 n=3 with binary `7d42…`:

- audit pass 3/3
- acceptance accepted 1/3
- completed **0/3**
- median wall 168.7s

That is worse than the shipped binary (`4b8e`, completed 1/3, acceptance 2/3).
The combined change was reverted. Do **not** ship R1+R3 together; the plan below
is intentionally one variable at a time.

## R1 alone result (also rejected)

Contract preflight alone (checklist step 0, reserve unchanged) on binary
`cdfa…`, T1 n=3:

- audit pass 2/3
- acceptance accepted 2/3
- completed **0/3**
- statuses: conditional, conditional, needs_evidence
- median wall 198.1s

This is worse than the shipped `4b8e` binary (completed 1/3, audit 3/3). R1 was
reverted. The remaining candidates are R3 alone, R2 (independent design-review
artifact), and R4 (read-only critic fallback).

## R3 alone result (also rejected)

Verification reserve 5 alone (no contract preflight) on binary `7265…`, T1 n=3:

- audit pass 3/3
- acceptance accepted 2/3
- completed **0/3**
- statuses: conditional, conditional, needs_evidence
- median wall 184.1s

R3 was reverted. R1, R1+R3 and R3 all fail to improve completion. **The
bottleneck is not budget or contract wording; it is the missing independent
design-review artifact.** Proceed to R2/R4.

## Experiments (one variable at a time)

### R1 — Acceptance contract preflight

At step 1 (or before the first write), ask the model to draft the acceptance
contract and compare it with the page design gate:

- 390/768/1440 widths
- horizontal scroll
- placeholders
- tap targets
- brief completeness
- primary CTA
- independent design review / unslop evidence

If a required field is missing, repair the contract before building.

**Metric:** completed rate on T1 n=5; acceptance accepted rate; total tools.
**Pass:** completed ≥ 3/5 with no wall-clock regression >20%.

### R2 — Design review artifact

Require one of:

- an `unslop`/`web-ui-audit` review artifact with findings, or
- a read-only critic subagent review with findings and disposition.

The acceptance receipt must reference the review artifact. Do not accept
“I checked it myself” as independent design review.

**Metric:** design-contract gaps at acceptance; completed rate.
**Pass:** design-gap conditional drops to 0/5; completed ≥ 4/5.

### R3 — Completion reserve

Reserve 5 tool calls for acceptance and design review, not 3; warn at
`max_tool_calls - 5`, and allow the reserved calls only for
`acceptance_gate`, `verify_artifact`, `preview_file`, `browser audit`, and
review tooling.

**Metric:** no-acceptance runs; completed rate; tool calls.
**Pass:** no-acceptance runs 0/5; completed ≥ 4/5.

### R4 — Read-only critic fallback

When no external design skill is installed, spawn a read-only critic with the
page, audit evidence and the acceptance contract. The critic returns findings
only; the main agent decides and writes the receipt. This is
read-parallel / write-serial.

**Metric:** design review evidence present; acceptance accepted; completed.
**Pass:** completed ≥ 4/5 without increasing duplicate edits.

## Order

1. R1 (cheap, no new tool).
2. R3 (small runtime change).
3. R2 (review artifact; may need skill/tool).
4. R4 (read-only critic; only if R2 is unavailable).

Do not change the page checklist, repair reserve and design nudge all at once;
the current n=3 already has high variance and needs one-variable attribution.

## Evaluation protocol

- T1 task, n=5 per variant, same model and binary except the variant.
- Report median and worst, not best.
- Primary metric: **completed rate**.
- Guardrails: final audit pass, acceptance accepted, wall clock, tool calls,
  duplicate calls, design gaps, crash/provider failures.
- A variant ships only if completed rate improves and wall clock does not
  regress by more than 20%.

## Non-goals

- No larger default context window.
- No more agents for show.
- No “completed” without an accepted receipt.
- No silent fallback when the requested design skill is missing.

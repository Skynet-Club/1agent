### Acceptance fix

- `src/tools/terminal.rs`: conservative read-only shell classifier;
  `terminal_exec` records `write=true|false`.
- `src/runtime.rs`: the completion gate ignores `terminal_create`,
  `terminal_output`, `terminal_destroy`, and read-only `terminal_exec`; a
  read-only shell check after acceptance no longer clears the receipt.
- `src/tools/acceptance.rs`: independent verifier labels are normalized to
  `verifier:…`; human verification still requires `human:`.
- `src/verification.rs`: criterion matching ignores case and extra whitespace.
- `src/provider.rs`: a later accepted receipt is decisive; every public and
  hidden criterion needs a result; read-only inspection prefers
  `read_file`/`jq`/`rg`/`ls` over interpreters.

Results (`docs/evidence/phase4-acceptance-fix-2026-11-23/`):

- Core 7 status met 18→21/24, model calls 6→5, tool calls 5→3, prompt tokens
  -25%, wall 17.2→16.5s.
- Full status met only 16→17/24; wall +7%.
- Product eval after the fix: 19/24 (79.16%), pass^3 3/8. This is a small-N
  regression signal, not a proven causal regression. Remaining failures are
  answer generation/repair, not acceptance.

## Post-run acceptance prototype

`scripts/post_accept.py` reads an existing journal and emits a deterministic
delivery manifest (artifact hashes, tool pairing, answer claims/sources). It is
read-only: no runtime behavior, ledger or answer changes.

`docs/evidence/post-accept-prototype-2026-11-23/`:

- Fix run: 48 1agent journals → accepted **43**, conditional 4, rejected 1.
- Runtime status met was 38/48; post-accept recovered **6** runtime misses.
- Zero-claim answers are covered by journal-derived evidence from recorded
  writes and verified artifacts.
- Remaining: 4 unpinned terminal writes, 1 provider error (no answer).
- Self-test covers accepted, tampered, missing observation, zero claims with
  derived evidence, directory sources and unpinned terminal writes.

### Delivery snapshot and provider retry

- The runtime now appends a `delivery_snapshot` event at final answer time:
  workspace root, file paths, sha256 and bytes (2048 files / 16 MB cap, internal
  directories skipped).
- Post-run acceptance verifies the snapshot and treats terminal writes as
  pinned when it is complete.
- The four previously `terminal_write_unpinned` cases were rerun with binary
  `40ab0e85…`: all four are accepted with zero snapshot mismatches
  (`docs/evidence/post-accept-prototype-2026-11-23/snapshot-smoke/`).
- Malformed provider tool-call JSON is now retryable within
  `max_provider_attempts`; other `InvalidResponse` cases stay non-retryable.

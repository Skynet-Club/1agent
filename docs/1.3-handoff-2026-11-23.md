### Acceptance fix

- `src/tools/terminal.rs`: conservative read-only shell classifier;
  `terminal_exec` records `write=true|false`.
- `src/runtime.rs`: the completion gate ignores `terminal_create`,
  `terminal_output`, `terminal_destroy`, and read-only `terminal_exec`; a
  read-only shell check after acceptance no longer clears the receipt.
- `src/tools/acceptance.rs`: independent verifier labels are normalized to
  `verifier:…`; human verification still requires `human:`.
- `src/verification.rs`: criterion matching ignores case and extra whitespace.
- `src/provider.rs`: a later accepted receipt is decisive; every public and
  hidden criterion needs a result; read-only inspection prefers
  `read_file`/`jq`/`rg`/`ls` over interpreters.

Results (`docs/evidence/phase4-acceptance-fix-2026-11-23/`):

- Core 7 status met 18→21/24, model calls 6→5, tool calls 5→3, prompt tokens
  -25%, wall 17.2→16.5s.
- Full status met only 16→17/24; wall +7%.
- Product eval after the fix: 19/24 (79.16%), pass^3 3/8. This is a small-N
  regression signal, not a proven causal regression. Remaining failures are
  answer generation/repair, not acceptance.

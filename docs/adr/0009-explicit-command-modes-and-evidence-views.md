# ADR 0009: Explicit TUI Command Modes and Journal-Derived Evidence Views

Status: accepted

Date: 2026-11-03

## Context

First-principles work requires deliberate framing, adversarial review, decision analysis
and failure analysis. Relying on keyword inference to select these modes makes command
behavior depend on incidental wording. In addition, a model-written summary cannot serve
as evidence that a run was structurally complete.

The TUI needs both model-assisted analysis and deterministic inspection of persisted facts.

## Decision

Add `AgentRuntime::run_with_mode` for application adapters that already have an explicit
mode. Normal tasks continue to use deterministic inference. Resume always uses the
checkpoint mode and cannot accept a different override.

The TUI maps:

- `/frame` to explicit evidence research;
- `/challenge` to explicit diagnosis;
- `/decide` to explicit decision analysis;
- `/postmortem` to explicit diagnosis.

The selected mode is written into `RunStarted` through the normal runtime journal path.

The following commands are provider-free:

- `/evidence` renders answer claims, sources, unknowns, conflicts and flip conditions from
  journal replay;
- `/audit` runs the deterministic journal audit over one run or all session runs;
- `/report` renders bounded execution, provider, answer, tool and evidence metadata from
  journal replay.

These views do not write new evidence and do not convert model priors into verified claims.

## Consequences

- First-principles command behavior is stable and inspectable.
- Offline mode can still inspect prior evidence and journal structure.
- Reports are reproducible from stored facts rather than regenerated by a model.
- Resume policy remains bound to the original checkpoint.
- Rendering is bounded to prevent arbitrary journal content from flooding the TUI.

## Verification

- explicit mode selection is tested for all four model-assisted commands;
- `/evidence`, `/audit` and `/report` are tested from a replay-backed answer;
- CLI E2E verifies the command sequence and cognitive modes in the session event log;
- PTY acceptance verifies `/frame -> /evidence -> /audit -> /report`;
- formatting, full tests, clippy and rustdoc pass.

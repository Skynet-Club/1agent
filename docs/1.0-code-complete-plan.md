# 1Agent 1.0 code-complete plan (local QA scope)

Status: **in progress**  
Date: 2026-11-17  
Owner: implementation + local QA session  
Source plan: Obsidian `1.0.0-Super-Partner-冲刺计划.md`  
Scope choice: **code-level 1.0 + local quality gates**. External audits, real
Windows/macOS GA hosts, signing/notarization, marketplace responsibility and
R1–R9 real-user metrics are explicitly **blocked**, not claimed as passed.

This document is the working plan, not a release announcement. A capability is
only "done" when its contract test, end-to-end command, evidence file, claims
entry and rollback/limit note exist. A blocked item is not zero; it means the
evidence does not exist on this host.

## 0. Completion definition

Local code-level 1.0 candidate means:

1. `./scripts/verify.sh` green (fmt, clippy, all tests, core-v3, claims
   structure).
2. Track Q `agent-loop-v1` ≥96/100 on a full run; failures named.
3. QG1 goal-closure evidence gate green (verification record bound; negative
   tests).
4. SDK/API read-only contract tests green, including `/v0/openapi`.
5. Windows GNU `cargo check --all-targets` and release link pass; macOS host
   toolchain is recorded as blocked if unavailable.
6. Local reliability evidence refreshed: HTTP surface e2e, TUI interaction,
   5-cycle soak, and a documented 8h-runtime evidence status.
7. A local `1.0.0-rc.2` release candidate can be packaged from a clean tagged
   tree; **no GitHub release and no GA claim** until external gates close.

Not in scope for this pass: third-party audit (SA100-68), real Windows/macOS
GA/signing/notarization (SA100-70), marketplace (SA100-71), mobile (SA100-73),
R1–R9 real-user metrics, A-Gate/W-Gate external checklists.

### T8 — Capability compiler (open-world task/tool resolution)

- Goal: stop treating tool choice as a prompt suggestion or a closed task
  taxonomy. Compile a task into a contract, derive capability requirements,
  resolve them against an open manifest registry, and verify the artifact.
- P0: `TaskContract` + open `DeliverableSpec`; `CapabilityManifest` data;
  resolver scoring; `resolve_capability` tool/CLI; explicit gap output; prompt
  rule for non-text deliverables; tests for unknown capabilities and new
  manifests without code changes.
- P1: runtime preflight enforcement (`needs_capability`/`needs_authorization`
  before acting), artifact verifier, install proposal with human approval.
- P2: strategy memory from capability paths, not task-type labels.
- Acceptance: a new tool/skill only needs a manifest; an unknown capability
  returns a named gap; no silent text fallback for a required artifact; every
  resolution has reasons and alternatives.
- Status: **P0/P1/P2 done locally**; tag `v1.0.0-rc.11` → `f352ba8`, archive
  SHA-256 `3f8dc770…`, binary `d469f9cf…`, `reproducible=true`, installed
  to `~/.local`; `TaskContract`, `DeliverableSpec`,
  `CapabilityManifest`, resolver, `resolve_capability` tool and prompt rule
  landed; manifests at `capabilities/manifests.json`; tests cover diagram gap,
  unknown capability, installed override and a new manifest without code.
  P1 runtime preflight/artifact verifier/install proposal and P2 capability-path
  memory are now implemented. See `docs/capability-compiler.md`.
- P1 status: runtime preflight returns `needs_authorization` for an unresolvable
  required capability and does not call the model; `verify_artifact` checks
  existence/size/MIME/schema/SHA-256/loopback preview; `propose_capability_install`
  + `capability approve-install --yes` records human approval without executing
  the command. Step-budget finalization is covered by rc.10.
- P2 status: `capability-paths.jsonl` records requirement → selected manifest →
  status → artifact_verified; `CapabilityMemory` boosts and reselects installed
  candidates on later runs. The runtime preflight resolution is journaled and
  preferred over the model's optional resolver call, so the recorded path is
  the one the run actually used. Eval does not write the store.
- Step-budget finalization: if the step budget ends after an accepted
  `acceptance_gate` receipt, the runtime gets one final tool-free answer turn;
  without a receipt it keeps `needs_evidence`. This fixes the smoke where a
  verified SVG was discarded at six steps.

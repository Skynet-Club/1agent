# 1Agent 1.0 code-complete plan (local QA scope)

Status: **in progress**  
Date: 2026-11-17  
Owner: implementation + local QA session  
Source plan: Obsidian `1.0.0-Super-Partner-冲刺计划.md`  
Scope choice: **code-level 1.0 + local quality gates**. External audits, real
Windows/macOS GA hosts, signing/notarization, marketplace responsibility and
R1–R9 real-user metrics are explicitly **blocked**, not claimed as passed.

This document is the working plan, not a release announcement. A capability is
only "done" when its contract test, end-to-end command, evidence file, claims
entry and rollback/limit note exist. A blocked item is not zero; it means the
evidence does not exist on this host.

## 0. Completion definition

Local code-level 1.0 candidate means:

1. `./scripts/verify.sh` green (fmt, clippy, all tests, core-v3, claims
   structure).
2. Track Q `agent-loop-v1` ≥96/100 on a full run; failures named.
3. QG1 goal-closure evidence gate green (verification record bound; negative
   tests).
4. SDK/API read-only contract tests green, including `/v0/openapi`.
5. Windows GNU `cargo check --all-targets` and release link pass; macOS host
   toolchain is recorded as blocked if unavailable.
6. Local reliability evidence refreshed: HTTP surface e2e, TUI interaction,
   5-cycle soak, and a documented 8h-runtime evidence status.
7. A local `1.0.0-rc.2` release candidate can be packaged from a clean tagged
   tree; **no GitHub release and no GA claim** until external gates close.

Not in scope for this pass: third-party audit (SA100-68), real Windows/macOS
GA/signing/notarization (SA100-70), marketplace (SA100-71), mobile (SA100-73),
R1–R9 real-user metrics, A-Gate/W-Gate external checklists.

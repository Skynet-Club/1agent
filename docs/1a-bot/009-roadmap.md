# 009 路线图与门禁

Status: executable plan  
Depends on: `000`–`008`  
Owns: 阶段、工作包、依赖、退出条件、交付物  
Does not own: 具体排期（由项目管理维护）

## 1. 总览

```text
G0 基础硬化（当前）
  → G1 1A Bot Alpha（单 Bot / Web / 一个真实场景）
  → G2 常驻与多通道
  → G3 多 Bot 团队与技能生态
  → G4 伙伴 OS（研究）
```

**硬规则**：上一阶段门禁未全部通过，不得启动下一阶段的产品开发。
可以在门禁未通过时做技术预研/原型，但不得对外声明"已进入下一阶段"。

## 2. G0：基础硬化

目标：让 1A + Workshop 具备承载 Bot 的内核能力，同时不破坏 V0 的可审计/只读边界。

### 2.2 G0 退出条件（全部满足）

- [ ] `ADR-003` 通过，V0 边界正式更新；回滚到只读有演练。
- [ ] Shell/Write/Network 在沙箱中可用；越权/逃逸/密钥测试全绿。
- [ ] 事件 → Gate → Eval → Ticket → Assignment → Worker → Report 的最小链路可跑。
- [ ] Worker 崩溃/daemon 重启后任务可恢复；重复投递不产生重复副作用。
- [ ] 记忆可写入/检索/遗忘；污染测试不触发动作。
- [ ] 技能可加载/版本化/回滚；恶意技能被拦截。
- [ ] 两个 provider 跑同一任务；成本/时延可观测。
- [ ] 审计可重建全部状态；收据可独立验证。
- [ ] `./scripts/verify.sh` 通过；红队无 P0。
- [ ] Surface API 契约冻结（OpenAPI/SSE），错误/幂等/trace 有契约测试。
- [ ] 至少一个真实场景在沙箱中端到端跑通（非演示数据）。

### 2.3 不做

- 不做 Web UI（只冻结 API 契约，见 `F0-13`）。
- 不做多 Bot/团队。
- 不做技能市场。
- 不做多租户/计费。

## 3. G1：1A Bot Alpha

目标：一个真实用户、一个 Bot、一个 Web 界面、一个真实场景，跑通"请求 → 执行 → 记忆 → 审批 → 交付 → 审计"。

### 3.1 范围

- 单 Bot（一个 Owner）。
- Web：对话、任务、记忆、审批、工件、审计、设置（最小集）。
- 一个通道：Web（IM 可选）。
- 一个场景：从以下选一个，不贪多：
  - A. 长期项目跟进（跨天任务 + 记忆 + 提醒）；
  - B. 代码/文档变更（读 → 改 → 测试 → PR/工件）；
  - C. 研究/决策支持（证据 → 结论 → 收据）。

### 3.2 工作包

| ID | 工作包 | 交付物 | 验收 |
|---|---|---|---|
| B1-01 | Bot 身份/人格/权限 | Bot profile、UserModel、AuthorityProfile | 创建/切换/隔离测试 |
| B1-02 | Web 对话 | 流式、中断、重试、证据展开 | 断线重连；移动端可用 |
| B1-03 | 任务页 | 列表/详情/停止/重试/接管 | 状态与 journal 一致 |
| B1-04 | 记忆页 | 浏览/编辑/删除/UserModel | 删除传播；来源可见 |
| B1-05 | 审批 | Web + 移动审批；默认安全 | 批准/拒绝/过期/重放测试 |
| B1-06 | 工件/审计 | 工件预览、时间线、收据 | 收据可独立验证 |
| B1-07 | 通知 | 需要你/结果可用；静默时段 | 不重复；可退订 |
| B1-08 | 场景端到端 | 一个真实场景，10+ 任务 | 成功率/介入率/成本报告 |

### 3.3 G1 退出条件

- [ ] 真实用户连续使用 2 周，完成 ≥20 个任务。
- [ ] 任务成功率 ≥ 预定阈值；无 P0 安全事故。
- [ ] 审批可在移动端完成；平均等待 < 预定阈值。
- [ ] 记忆可查/可删；用户能理解"为什么记得"。
- [ ] 审计完整率 100%；收据可验证。
- [ ] 成本/任务在预算内。
- [ ] 用户访谈：≥ 预定比例的"愿意继续用"。

## 4. G2：常驻与多通道

目标：Bot 不再依赖打开 Web；事件驱动、后台工作、跨通道。

工作包：

| ID | 工作包 | 验收 |
|---|---|---|
| B2-01 | 常驻 daemon/自启 | 重启恢复；空闲低资源 |
| B2-02 | 定时/条件例程 | 准点/幂等/可暂停 |
| B2-03 | Webhook/CI/邮件入口 | 去重/鉴权/限流 |
| B2-04 | IM 网关（Telegram/飞书/Slack） | 对话/审批/状态；格式正确 |
| B2-05 | 后台 job/并发槽 | 超时/杀树/公平调度 |
| B2-06 | 语音（可选） | 录音指示/静默/转文字 |

退出条件：

- [ ] 连续运行 7 天无人工重启。
- [ ] 事件不丢/不重；后台任务可恢复。
- [ ] 至少两个通道状态一致。
- [ ] 通知不刷屏；静默生效。

## 5. G3：多 Bot 团队与技能生态

目标：一个 Owner 可以有多个专家 Bot，协作完成跨领域工作。

工作包：

| ID | 工作包 | 验收 |
|---|---|---|
| B3-01 | Router + 专家 Bot | 派工/汇总/冲突处理 |
| B3-02 | 共享工作区/消息板 | 权限/隔离/审计 |
| B3-03 | 技能市场 | 发布/安装/扫描/签名/回滚 |
| B3-04 | 自我进化闭环 | 候选→评测→shadow→激活→监控→回滚 |
| B3-05 | 团队记忆/用户模型 | 共享边界/隐私 |
| B3-06 | 管理/配额/账单（如多租户） | 隔离/限额/审计 |

退出条件：

- [ ] 多 Bot 协作完成一个真实跨领域项目。
- [ ] 技能安装/更新/回滚可审计；恶意技能被拦截。
- [ ] 进化闭环有真实 held-out 证据；负迁移可控。
- [ ] 租户隔离测试通过（如启用）。

## 6. G4：伙伴 OS（研究）

方向（不承诺）：

- 长期关系模型：跨月/跨年的偏好、边界、承诺。
- 主动协作：在规则内主动发现机会/风险。
- 跨设备/跨表面连续。
- 记忆/技能的可解释与可携带。
- 安全：更强隔离、审计、回滚。

G4 只做研究/原型，不进入产品承诺。

## 8. 角色

| 架构 | 领域模型、ADR、跨模块一致性 |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 授权模型做晚 | 返工/安全事故 | F0-01 先做，其他依赖它 |
| 记忆过度设计 | 成本/延迟/污染 | 先 MVP，评测驱动 |
| Web 功能膨胀 | 延期 | Alpha 只做一个场景 |
| 跨平台沙箱 | Windows/macOS 阻塞 | 先 Linux，其他适配 |
| 多 Bot 过早 | 复杂度爆炸 | G3 再做 |
| 进化失控 | 质量漂移 | 人工审批 + shadow + 回滚 |
| 评测造假 | 错误自信 | 预注册 + held-out + 红队 |

## 10. 现在可以开工的顺序

1. `F0-01` 授权 ADR + 策略 schema（阻塞最多）。
2. `F0-03` 事件/Gate（可与 F0-01 并行）。
3. `F0-02` shell/沙箱（依赖 F0-01）。
4. `F0-04` Ticket/Mandate（依赖 F0-01/03）。
5. `F0-06` 记忆 MVP（依赖 F0-03）。
6. `F0-08` 模型网关（独立）。
7. `F0-11` 评测基线（随功能逐步补）。

每个工作包完成时更新本文件的勾选状态，并在 `010-governance.md` 记录偏差。

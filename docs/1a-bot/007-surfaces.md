# 007 界面与交互

Status: design normative  
Depends on: `000-thesis.md`、`001-domain.md`  
Owns: Web/TUI/IM/Voice 的信息架构、交互规则、设计语言  
Does not own: 实现组件（由前端仓库决定）、API（`002`）

## 1. 设计目标

界面不是"聊天窗口 + 侧边栏"。它要回答三个问题，按顺序：

1. **现在需要我做什么？**
2. **系统是否健康、在做正确的事？**
3. **这件事从触发到结果的经过是什么？**

健康状态不占空间；需要人的事优先；其余折叠。

## 2. 表面矩阵

| 表面 | 角色 | 首屏 | 备注 |
|---|---|---|---|
| Web | 主界面 | 需要你 + 对话 | 桌面/移动响应式 |
| TUI | 开发者/高级用户 | 对话 + 状态 | 保留现有能力 |
| IM | 轻量交互 | 对话 | Telegram/飞书/Slack/邮件 |
| Voice | 免手操作 | 语音 | 后续 |
| API | 集成 | — | 无 UI |

规则：

- 所有表面共享同一 Bot 身份、记忆、工单；不是不同产品。
- Web 是功能最全的；IM 只做"够用"的交互；TUI 保留调试/高级能力。
- 会话可以在表面之间迁移（Web ↔ 手机 ↔ IM），状态一致。

## 3. Web 信息架构

```text
┌────────────────────────────────────────────────────────────┐
│ Bot 切换 · 搜索 · 通知 · 设置                               │
├──────────┬─────────────────────────────────────────────────┤
│ 需要你   │  主内容区                                        │
│ 对话     │  - 对话/任务/记忆/技能/工件/审计                  │
│ 任务     │                                                 │
│ 记忆     │                                                 │
│ 技能     │                                                 │
│ 工件     │                                                 │
│ 审计     │                                                 │
└──────────┴─────────────────────────────────────────────────┘
```

### 3.1 需要你（Home）

只显示：

- 等待审批的动作；
- 等待回答的问题；
- 失败/阻塞需要决策的工单；
- 即将到期/逾期的承诺。

每条包含：一句话、影响、默认动作、截止时间。空状态明确说"现在没有需要你的事"。

### 3.2 对话

- 流式输出；可中断；可重试。
- 消息显示：谁说的、依据、动作、成本、时间。
- 默认简洁；"展开详情"看证据/工具调用/记忆引用。
- 不在对话里堆系统状态；状态在任务/审计页。

### 3.3 任务（Tickets）

- 列表：状态、负责人（Bot/人）、下一步、截止。
- 详情：触发、授权、计划、执行、报告、工件、审计。
- 操作：暂停、停止、重试、接管、审批。
- 状态用领域术语，不暴露内部 code。

### 3.4 记忆

- 按类型/项目/时间浏览。
- 每条显示：内容、来源、置信度、有效期、被谁使用过。
- 可编辑、删除、标记错误。
- UserModel 单独展示：偏好、边界、项目、沟通风格。
- 删除必须确认；显示影响范围。

### 3.5 技能

- 列表：名称、描述、版本、来源、使用次数、成功率。
- 详情：SKILL.md、版本历史、评测、使用记录。
- 操作：启用/禁用、锁定、回滚、审批新版本。

### 3.6 工件

- 文件、截图、PR、报告；按任务分组。
- 预览/下载；来源与摘要。
- 不展示无法验证的"完成"。

### 3.7 审计

- 时间线：触发 → 决定 → 授权 → 派工 → 执行 → 报告 → 验收。
- 每个动作可展开：参数、结果、成本、审批。
- 支持导出收据；收据可独立验证。

### 3.8 设置

- Bot：名称、人格、模型策略、权限、工作区、通道。
- 记忆：自动写入开关、保留期、共享范围。
- 技能：来源、自动更新、锁定。
- 通知：频率、通道、静默时段。
- 安全：审批规则、密钥、审计保留。
- 账单/配额（后续）。

## 4. 页面状态

每个页面必须定义：

| 状态 | 要求 |
|---|---|
| 空 | 说明为什么空、下一步做什么 |
| 加载 | 骨架屏；不阻塞其他区域 |
| 错误 | 原因、可重试、降级路径 |
| 离线 | 显示最后同步时间；可排队操作 |
| 无权限 | 说明缺什么权限、如何申请 |
| 限流/超预算 | 说明限额、重置时间、如何调整 |

禁止：空白页、无限 spinner、只显示 "Error"。

## 5. 交互规则

1. **一次一个问题**：带 2–3 个选项，一个默认；不用 yes/no。
2. **默认安全**：危险动作默认"取消/暂缓"。
3. **确认一次**：开始实质工作前确认对象和结果；之后不重复确认。
4. **可中断**：长任务随时可停；显示停止点与影响。
5. **可追溯**：每个结果可展开证据；每个动作可看收据。
6. **不重复**：同一信息不在多个页面重复；用链接。
7. **不打扰**：健康状态不通知；同一事件不重复通知；静默时段生效。
8. **诚实**：草稿标未完成；失败说失败；不把"已提交"说成"已完成"。
9. **成本可见**：长任务显示预计/已用成本与时间。
10. **键盘优先**：Web 支持快捷键；TUI 保持现有键位。

## 6. 设计语言

- **层级**：一个主色（品牌蓝/绿），其余灰阶；语义色只用于状态（成功/警告/危险）。
- **密度**：信息密度高但不拥挤；列表行高一致；数字右对齐。
- **字体**：等宽用于代码/ID；正文用系统字体；中文优先。
- **圆角/边框**：统一圆角；边框只用于分组，不用于装饰。
- **动效**：只用于状态变化；尊重 `prefers-reduced-motion`。
- **暗色优先**：默认暗色；支持亮色。
- **可访问性**：对比度 ≥ WCAG AA；键盘可达；屏幕阅读器标签；不只靠颜色表达状态。
- **国际化**：中英文；术语表为准；日期/时区/数字本地化。

## 7. TUI

保留现有 TUI 作为开发/高级界面：

- 对话、命令、任务、审计。
- 与 Web 共享 API/状态。
- 不要求功能对等；但关键操作（停止/审批/查看证据）必须可用。
- 主题/键位/鼠标保持现有规范；新增 Bot/任务页遵循现有菜单风格。

## 8. IM

- 只做轻量交互：对话、审批、状态、结果。
- 消息短；一条消息一个目的；不刷屏。
- 审批用按钮/编号；支持"批准/拒绝/稍后"。
- 长内容用链接回 Web。
- 平台差异（Telegram/飞书/Slack/邮件）由适配器处理；领域不变。

## 9. Voice（后续）

- 只做"免手"场景：查询状态、批准/拒绝、简短指令。
- 长内容转文字/链接。
- 语音输入需要明确录音指示；默认不录音。
- 语音输出尊重静默时段。

## 10. 通知

- 分级：需要行动 / 结果可用 / 信息。
- 默认只发前两类；信息类进收件箱。
- 聚合：同一任务的多条更新合并。
- 静默：夜间/专注时段；紧急（失败/安全）可例外。
- 退订：一键关闭某类通知。

## 11. Web Alpha 验收标准

- [ ] 首屏 1s 内显示"需要你"与最近对话。
- [ ] 对话流式输出，可中断/重试。
- [ ] 任务详情能看到触发、授权、执行、报告、工件、审计。
- [ ] 记忆可查看/编辑/删除；删除有确认与影响说明。
- [ ] 审批可在 Web 和移动端完成。
- [ ] 断线重连不丢消息；离线可查看最后状态。
- [ ] 空/加载/错误/无权限状态完整。
- [ ] 键盘可达；对比度达标；暗色/亮色可用。
- [ ] 所有外部动作都能展开收据。

## 12. 反例

- 首页放一堆图表，但没有"需要你"。
- 对话里混入工具日志/系统状态。
- 记忆页只给一个搜索框，不显示来源/有效期。
- 审批弹窗只写"是否允许？"没有范围/影响/默认。
- 用 toast 通知不可逆动作完成。
- 移动端只能看不能批。

# 008 质量与评测

Status: design normative  
Depends on: `000-thesis.md`、`001-domain.md`  
Owns: 测试体系、基准、发布门禁、指标、红队  
Does not own: 具体 CI 实现（可后续补充）

## 1. 原则

1. **可重跑**：每个结论都有命令/测试能复现。
2. **分层**：单元 → 契约 → 集成 → 端到端 → 红队。
3. **Held-out**：调参与评测分离；不泄漏。
4. **负迁移**：不仅看"变好"，也看"有没有变坏"。
5. **审计**：没有 journal 的"通过"不算通过。
6. **诚实**：不把 contract fixture 当模型质量；不把一次运行当稳定性。

## 2. 测试金字塔

| 层级 | 范围 | 工具 | 门禁 |
|---|---|---|---|
| 单元 | 纯函数/状态机 | `cargo test --lib` | 必须 |
| 契约 | JSON schema/API/事件 | 契约测试 | 必须 |
| 集成 | 内核 + 存储 + 工具 | `cargo test` | 必须 |
| 端到端 | Web/CLI/IM | PTY/浏览器测试 | 必须 |
| 红队 | 注入/越权/泄漏 | 脚本 + 人工 | 发布前 |
| 长跑 | 数天/数月 | 沙箱环境 | 阶段门禁 |

要求：

- 每个领域不变量至少一个测试（见 `001-domain.md` §4）。
- 每个状态机转换至少一个测试（合法/非法）。
- 每个工具至少一个权限/超时/输出边界测试。
- 每个外部声明进 `docs/claims.md`，附可执行证据。

## 3. Agent 级评测

### 3.1 任务套件

- 真实任务：来自用户/团队，匿名化。
- 合成任务：覆盖边界/失败模式。
- 长任务：跨小时/跨天，检查恢复与记忆。
- 多轮：偏好变化、纠正、追问。

### 3.2 指标

| 指标 | 定义 |
|---|---|
| Task success | 无人工返工即被接受 |
| Intervention rate | 需要人回答/审批的比例 |
| Attention cost | 每任务通知/问题数 |
| Time to value | 从请求到可用结果 |
| Cost/task | 模型 + 执行 + 存储 |
| Recovery rate | 中断后成功恢复比例 |
| Audit completeness | 可重建动作 / 总动作 |

### 3.3 评测协议

- 预注册：指标、阈值、任务集、评分规则先写后跑。
- 分组：train/eval/held-out 不重叠。
- 盲评：人工评分不知道版本。
- 重复：至少 N 次，报告分布而非单点。
- 失败分析：每个失败归类，不掩盖。

## 4. 记忆评测

见 `004-memory.md` §10。必须包含：

- LongMemEval / MemoryAgentBench / EvoMemBench（外部校准）。
- 1A 自有：重复任务、偏好变化、过期事实、负迁移、选择性遗忘、污染。
- 成本/延迟。

注意 EvoMemBench 的结论：长上下文基线仍很强，没有单一记忆形态通吃。
不得声称"记忆提升了所有任务"。

## 5. 技能/进化评测

见 `005-evolution.md` §6。必须包含：

- baseline vs candidate；
- held-out；
- 负迁移；
- 安全扫描；
- shadow 期真实任务；
- 激活后漂移监控。

## 6. 安全红队

| 类别 | 用例 |
|---|---|
| Prompt injection | 网页/Issue/邮件/技能中的指令 |
| 越权 | 读越界、写越界、执行未授权命令 |
| 密钥 | env、日志、错误、工具输出 |
| 记忆 | 投毒、过期、跨租户、删除不彻底 |
| 技能 | 恶意 SKILL.md、隐藏字符、危险脚本 |
| 资源 | 死循环、fork 炸弹、超大输出 |
| 审批 | 重放、过期、跨 Ticket、伪造 |
| 审计 | 篡改、缺事件、哈希链断裂 |

要求：

- 红队用例进入 CI（可离线）。
- 每次发布跑一遍；高危问题阻断发布。
- 发现的问题记录在 `010-governance.md` 风险登记。

## 7. 发布门禁

### 7.1 每次合并

```bash
./scripts/verify.sh
```

必须通过：

- fmt / clippy `-D warnings`；
- 单元/集成/E2E；
- claims 结构检查；
- 文档链接检查（新增）。

### 7.2 每个阶段

- 全量测试 + 红队；
- 性能/成本基线；
- 恢复演练（kill -9/断电/重复投递）；
- 跨平台（Linux/macOS/Windows 至少一个）；
- 安全评审；
- 文档/ADR 更新。

### 7.3 对外发布

- `docs/claims.md` 每条 ✅ 有可执行证据；
- CHANGELOG；
- 可复现构建；
- 回滚方案；
- 已知限制。

## 8. 指标看板

必须可导出：

- 任务成功率/失败原因；
- 人工介入率/审批等待；
- 注意力成本；
- 成本/时延；
- 记忆命中/污染/遗忘；
- 技能复用/负迁移；
- 审计完整率；
- 崩溃/恢复。

不得只展示"好看"的指标；失败与未知必须可见。

## 9. 数据与标注

- 真实任务匿名化；保留语义。
- 标注者独立；计算一致率（kappa），不只报单人不一致。
- 标注指南版本化；争议记录。
- 合成数据标注来源；不得冒充真实。
- 评测集冻结；变更需新版本。

## 10. 回归与事故

- 每次线上/测试失败 → 复现 → 测试 → 修复 → 回归。
- 事故分级：P0 安全/数据丢失；P1 核心功能；P2 体验。
- P0/P1 必须有 postmortem（不追责，追机制）。
- 修复后更新红队/测试集，防止复发。

## 11. 反例

- "测试都过了"但没跑 E2E。
- 用一次模型输出证明稳定性。
- 只报平均分，不报失败分布。
- 把 fixture 当真实任务。
- 记忆评测只用合成数据。
- 安全测试只做 happy path。

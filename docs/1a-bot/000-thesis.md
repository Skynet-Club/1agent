# 000 命题与不变量

Status: normative  
Depends on: —  
Owns: 产品定位、不变量、非目标、成功指标  
Does not own: 术语（见 `001-domain.md`）、架构（见 `002-architecture.md`）

## 1. 一句话命题

**1A Bot 是一个长期在线、有记忆和技能、可审计、只在需要时出现的超级智能伙伴。**

拆开：

- **长期在线**：不是打开终端才有；它有自己的工作区和后台任务。
- **有记忆**：记得你、你的项目、你的偏好、你的边界；记忆可查、可改、可删。
- **有技能**：把做过的非平凡流程沉淀成可复用技能，按需加载。
- **可审计**：每个决定、每次执行、每条记忆都能从 journal 重建。
- **只在需要时出现**：默认安静；只在有人必须行动或结果可用时说话。
- **伙伴**：关系是长期的，不是一次会话；它对你负责，而不是对"完成任务"负责。

"Super" 不是"更强"，是 **supervisor + persistent**：它站在多个 worker 之上，持续存在。

## 2. 为什么不是另一个 copilot

| 维度 | Copilot | Chatbot | 1A Bot |
|---|---|---|---|
| 时间尺度 | 一次补全 | 一次对话 | 长期关系 |
| 记忆 | 无/会话内 | 会话 | 跨会话、跨通道、受治理 |
| 工作方式 | 人驱动 | 人驱动 | 事件驱动 + 人授权 |
| 权限 | IDE 内 | 无 | 沙箱 + 策略 + 审批 + 审计 |
| 成功标准 | 代码被接受 | 回答看起来对 | 事情真的完成，且可追溯 |
| 失败方式 | 建议错误 | 幻觉 | 可回滚、可审计、可停止 |

## 3. 六条不变量（任何功能不得违反）

### I-1 证据先于声称

没有 journal 可重建的证据，不得声称"完成、验证、修复、已发送"。

**可测试**：每条对外结论必须能链接到 `journal` 事件或 artifact 摘要；`audit` 必须失败于无证据的完成声明。

### I-2 不可逆动作先授权

写文件、执行命令、发消息、合并 PR、花钱，必须落在已授权的 Ticket/Mandate 内。
授权粒度是**工单**，不是每条命令；但人必须能随时 stop / pause。

**可测试**：无 Mandate 的动作被拒绝；越权动作被拒绝；stop 在下一个安全点生效。

### I-3 注意力预算

每条消息、每个问题、每个设置、每个面板元素都要比它消耗的注意力更值钱。
默认安静；健康状态不占空间；一次只问一个具体问题。

**可测试**：一次任务的通知数、问题数有上限；无行动价值的消息被抑制；面板首屏只显示"需要你"的事。

### I-4 记忆受治理

记忆是数据，不是指令。每条记忆必须有来源、作用域、版本、有效期；可遗忘、可回滚。
记忆不得改变权限、策略或工具白名单。

**可测试**：检索结果带 provenance/taint；被污染记忆不能触发动作；遗忘后不可再检索；回滚可恢复。

### I-5 Provider 中立、本地优先

模型、执行后端、存储都可以替换；默认数据留在用户侧；不绑定单一模型厂商。

**可测试**：同一任务可在至少两个 provider 上运行；核心契约不依赖 provider SDK；导出/迁移可用。

### I-6 一切可重建

触发、决定、授权、派工、执行、报告、验收都能从持久记录重放；重启不丢。

**可测试**：kill -9 后恢复；重复投递幂等；审计可重建状态。

## 4. 非目标

以下不是 1A Bot 的目标，出现即为范围蔓延：

- 不是通用聊天机器人，不追求"什么都能聊"。
- 不是无授权的全自动自治体；没有 Mandate 不执行。
- 不是"记住一切"的黑箱；记忆必须可解释、可删除。
- 不是模型训练项目；不微调基础模型（L4 研究见 `005-evolution.md`，不属于产品承诺）。
- 不是单一厂商的壳；不做 provider 锁定。
- 不是只服务开发者；Web Alpha 的首要用户是知识工作者。
- 不是多租户 SaaS 的第一天；先做单用户/单团队自托管，再谈多租户。

## 5. 用户与场景

### 5.1 首要用户

- 独立开发者/小团队负责人：同时推进多个项目，注意力碎片化。
- 知识工作者：大量信息、会议、文档、决策，需要有人替他跟进。
- 创作者/研究者：长期项目，需要记忆、资料整理、定期回顾。

### 5.2 前三个必须做好的场景

1. **长期项目跟进**：跨天、跨会话记住目标、决定、未完成事项；主动提醒但不骚扰。
2. **研究/决策支持**：收集证据、区分事实与假设、给出可翻转的结论。
3. **可审计的执行**：在授权范围内跑命令、改文件、开 PR、发消息，并能证明做了什么。

前三个场景没有跑通之前，不做"万能助手"。

## 6. 体验原则

1. **一个声音**：用户只跟一个 Bot 对话；内部可以有多个 worker，但对外只有一个身份。
2. **先确认一次**：开始实质工作前，用一句话确认对象和预期结果；之后保持安静。
3. **只在需要时说话**：结果可用、需要决定、无法完成，三种情况之外不发消息。
4. **一次一个问题**：结构化、具体、带选项；不把问题埋在长报告里。
5. **按影响停止**：局部改动做到可 review；需要设计决策时停下问，不硬做。
6. **诚实**：草稿标未完成；失败说失败；不绕过限制来避免提问。
7. **可追溯**：每个结果都能展开看到证据、动作、成本、时间。
8. **可后悔**：不可逆动作前确认；能回滚的给回滚；不能回滚的说清楚。

## 7. 成功指标

北极星指标：**每周被用户接受的、可审计的完成事项数**（Accepted Auditable Outcomes / week）。

辅助指标：

| 指标 | 定义 | 目标方向 |
|---|---|---|
| 任务成功率 | 无人工返工即被接受的任务 / 总任务 | ↑ |
| 人工介入率 | 需要人回答/审批的任务 / 总任务 | ↓，但不牺牲正确性 |
| 注意力成本 | 每条完成事项产生的通知/问题数 | ↓ |
| 首次价值时间 | 新用户从进入到第一个有用结果 | ↓ |
| 记忆精确率 | 检索到的记忆中被用户确认有用的比例 | ↑ |
| 记忆污染率 | 被污染/过期记忆被使用的比例 | ↓ |
| 审计完整率 | 可重建的动作 / 总动作 | 100% |
| 成本/任务 | 模型 + 执行 + 存储 | ↓ |
| 留存 | 4 周后仍在使用 | ↑ |

指标不得单独使用；每个指标必须绑定可重跑的测量方法，见 `008-quality.md`。

## 8. 阶段边界

- **现在到 G0**：只做基础设施硬化；Bot Alpha 不开工。
- **G0 通过后**：Bot Alpha（单 Bot、Web、一个真实场景、记忆/技能/审批/审计的最小闭环）。
- **Alpha 通过后**：常驻、多通道、多 Bot、技能生态。

G0 的退出条件见 `009-roadmap.md`；未通过前，任何"1A Bot 已可用"的对外表述都不成立。

## 9. 与其他产品的关系

| 产品 | 我们学什么 | 我们不做什么 |
|---|---|---|
| Claude Code | 两层记忆、渐进披露、subagents、hooks | 不做封闭生态、不做只服务 IDE |
| Codex | OS 沙箱、执行策略分级、apply_patch、daemon | 不照搬复杂度、不做纯 CLI |
| Hermes | 技能自我进化、Bot Mode、多通道、技能市场 | 不默认放开技能写入、不做无治理的自动学习 |
| Pi | 极简内核、扩展、热重载 | 不默认没有权限模型 |
| Grok Bot | 常驻、自己的电脑、持久关系 | 不做云锁定 |
| DSH Super-agent | Router/Worker、事件、Mandate、注意力 | 不做无安全边界的 worker |

## 10. 反例（出现即打回）

- "先让模型自己决定要不要执行。"
- "记忆越多越好，全部塞进上下文。"
- "先上线再补权限。"
- "用户没问，但我们可以多发一条消息。"
- "这个功能竞品有，我们也要有。"
- "先用 prompt 约束，不用代码强制。"

以上每一条都违反至少一条不变量。违反不变量的需求，先开 ADR，不得直接实现。

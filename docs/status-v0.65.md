# Status v0.65.0

Date: 2026-11-02
Status: content-bound experience evidence implemented

## Changes since v0.64.0

- Candidate adds `evidence_sha256`.
- Digest covers:
  - domain separator;
  - sorted unique evidence event sequences;
  - canonical serialized event bytes.
- Proposal computes and stores the digest.
- Review, approval and activation require source events for digest-bound candidates.
- Source revalidation checks audit state, run identity and evidence content.
- Aggregate experience review/approve/activate commands accept `--journal`.
- Legacy candidates without a digest retain their prior read behavior.

## Known limitations

- Canonical serialization is JSON generated by this binary, not original raw journal bytes.
- Legacy candidates without digests are not retroactively protected.
- Source journal availability is required at each bound transition.
- Verification/evaluation does not independently reread the source journal.

## Next requirement

Restrict which journal events can serve as experience evidence:

1. accept evidence-bearing observations and answers;
2. reject lifecycle-only events such as run start or route selection;
3. expose stable invalid-evidence-kind errors;
4. keep digest semantics deterministic;
5. test each accepted and rejected event class.

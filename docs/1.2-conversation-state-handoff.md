## P1.1 — ledger rebuild (landed)

- `1agent ledger rebuild [--workspace PATH] [--journal-dir DIR] [--json]`,
  workspace defaults to the current directory.
- Scans `~/.1a/journals/*.jsonl`; a journal belongs to the workspace when its
  first read root is that workspace or one of its write artifacts lives under
  it. Derivation is the same `work_ledger::entry_from_events` used by live
  runs, so live and backfilled entries cannot drift.
- Merges by `run_id`, sorts by journal timestamp, writes the ledger atomically;
  a second run appends 0.
- Real backfill: 182 journals scanned, 161 entries added to `/home/skynet`,
  1 entry to `/home/skynet/work/join-us`. Mock regression in join-us:
  `interaction=answer`, ledger context injected, newest entry shows the build
  run with `reused: index.html`.
- Known limit: files written by `terminal_exec` (e.g. `index.html` produced by
  `build.py`) carry no `path`/`sha256` metadata, so the ledger records them as
  `reused` (via `verify_artifact`) but not as fresh artifacts. Old journals
  also predate `InteractionModeSelected`, so their `mode` is `unknown`.

## What is thin (the user's critique)

P0 is deliberately narrow. It fixes the provenance/continuation failure, not
general intent understanding:

- Existing journals need a one-time manual `1agent ledger rebuild`; there is no
  automatic backfill and no hint when a workspace ledger is empty.
- Ledger is keyed by the first `read_root`; the TUI default `/home/skynet`
  shares one ledger across project subdirectories.
- Mode classification is heuristic (question shape, prior reference, action
  verbs); it can misjudge nuanced requests.
- Answer mode still allows up to two read-only tools.
- Ask mode is only a vague-change/short-follow-up clarification, not a full
  clarification planner.
- No active-task binding, no intent echo in the TUI, no mode badge.
- General evolving-intent ambiguity remains open (IntentFlux shows state alone
  only partially closes the gap).

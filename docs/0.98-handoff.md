## 3. 0.98 scope and order

Theme: **Real World**. Do these as vertical slices, not a broad feature sweep.

Overall plan (research, selection, 11-week schedule, gates): `docs/0.98-development-plan.md`.

1. **Onboarding + CLI IA (first slice)**
   - `1agent setup` guided first run; idempotent, resumable, `--check`,
     non-interactive flags.
   - Provider choice (DeepSeek / OpenAI-compatible / Ollama), masked key,
     `/v1/models` probe, model select, 0600 storage.
   - Permission preset: read-only / safe (write + approval) / full local.
   - Workspace/read roots, 30-second smoke task, journal path, `doctor` summary.
   - Public command layer: `setup`, `tui`, `run`, `doctor`, `model`,
     `permissions`, `audit`, `replay`, `skills`, `schedule`, `serve`,
     `uninstall`; advanced commands behind `1agent help advanced`/`--all`.
   - `1agent status` (version/platform/model/permissions/data dir/last run).
   - Shell completions, man page, consistent `--json`, `error:` + `next:`.
   - Acceptance: new user completes a first successful task in ≤5 minutes with
     no manual file edits; setup is idempotent; read-only refusal is explicit.

2. **Computer-use / browser write sandbox**
   - Per-task browser profile; click/type/screenshot/record; credential proxy;
     human takeover; single-step authorization; irreversible-action confirmation.
   - Reuse the existing CUA policy (`cua-check`, `CuaPlan::authorize`); do not
     invent a second policy path.
   - Red-team: prompt injection, SSRF, credential exfiltration, branch steering.

3. **MCP connectors**
   - HTTP/SSE/OAuth, discovery, schema/risk/timeout/audit; keep the 0.97
     rule that server annotations cannot lower local permissions.

4. **Skill loop**
   - Capture → eval → activate → canary → rollback; held-out eval and negative
     transfer; keep inert drafts until human activation.

5. **Daemon / trigger / routine / watchdog**
   - Cross-restart dedupe, escalation, health, alerts; no automatic resume/kill.

6. **Three real workflows + red team**
   - Pick three real user workflows, capture journals/evidence, then run
     prompt-injection/SSRF/secret/permission red-team cases.

7. **Docs and release**
   - Update `FEATURES`, `manual`, ADRs, Obsidian; build a Linux package only
     after gates pass.

## 4. Development workflow (must follow)

**requirement → design/ADR → implementation → tests → verification → audit →
docs → next**

- Think before coding; surface ambiguity instead of silently choosing.
- Simplicity first; no single-use abstractions, no speculative features.
- Surgical changes; match existing style; each changed line traces to a request.
- Verify before done: `cargo fmt --check`, `cargo clippy --offline --all-targets
  -- -D warnings`, `cargo test --offline -j 2`, `./scripts/verify.sh`; real
  command/evidence where tests are not enough.
- Every model-visible input must be rebuildable from the journal; tool calls and
  observations stay paired.
- No credentials in argv/logs/journals; no AI byline in commits/docs/releases.
- Public push/tag requires explicit owner confirmation.
- Update `docs/architecture.md`, ADR and Obsidian when a contract changes.

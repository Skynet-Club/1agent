# 1AO P3 — Action/object policy v0 (2026-11-19)

Scope: typed-action policy v0. It extends the existing Authority/ExecutionGate
surface; it is not object-level RBAC, property/cell security, or an Ontology MCP
server.

## Behavior

- `AuthorityProfile` gains optional `allowed_action_types` and
  `allowed_object_types` (empty = no extra restriction, `*`/prefix wildcards
  supported). Existing configs remain valid.
- `PolicyRequest` gains optional `action_type` and `object_types`.
- `ExecutionGate` derives both from the built-in `ActionType` registry by tool
  name; ordinary tools carry no action/object type and are unaffected.
- A mismatch denies before execution with a concrete reason, so a denied typed
  action has no side effect and the decision is journaled by the existing gate
  action record.
- `governed_task_graph` PolicyRequests explicitly carry no action/object type
  in v0; task-graph object scopes are future work.

## Limits

- Scope is the coarse set of ActionType object types, not object instances.
- No property/cell-level security, no row filters, no per-object ACLs.
- Task-graph `PolicyCheck` does not yet carry object scope.
- Wildcards use the existing prefix matcher; there is no policy compiler or
  conflict resolver.
- Action metadata is built from the built-in registry; third-party ActionTypes
  would need an explicit registration path.

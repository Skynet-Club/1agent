## What this proves

- `/inbox` is registered as a core command.
- It is a transcript command, not a command panel.
- The command-count and drawer tests were updated for the new entry.
- The display path reads the default inbox store and prints open/due-snoozed
  items; it does not mutate state.

## What this does not prove

- That a real user sees the expected output in a live terminal; the full PTY
  interaction check is separate.
- That the user can resolve/snooze from the TUI; those actions remain CLI-only.
- Cross-platform behavior; the tests ran on Linux only.

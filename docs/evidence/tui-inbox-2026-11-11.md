## What this proves

- `/inbox` is registered as a core command.
- It is a transcript command, not a command panel, and supports inline args.
- `parse_action` accepts `resolve <id> <terminal status> [note]` and
  `snooze <id> <until_ms>`; it rejects unknown actions, non-terminal resolve
  statuses, missing ids and invalid numbers.
- `InboxStore::apply_action` resolves or snoozes the item.
- The display path reads the default inbox store and prints open/due-snoozed
  items; listing does not mutate state.

## What this does not prove

- That a real user sees the expected output and can complete an action in a
  live terminal; the full PTY interaction check is separate.
- That the action is authorized by Authority/Policy/Approval; the inbox action
  only mutates the inbox store.
- Cross-platform behavior; the tests ran on Linux only.

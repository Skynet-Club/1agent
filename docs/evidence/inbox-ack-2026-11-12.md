## What this proves

- `EscalationState` persists an acknowledged id and reports the first insert
  only; reopening the state file preserves it.
- An acknowledged item is still present in the projection, but its level is
  `null` and its reason says `item is acknowledged`; no notification is
  attempted.
- `inbox ack` is idempotent at the CLI: the first call reports `new: true`,
  the second `new: false`.
- Acknowledging does not resolve or otherwise change the inbox item.

## What this does not prove

- That the operator actually read the item; acknowledgement is a local policy
  signal.
- Per-channel acknowledgement; all targets sharing one state file share the
  acknowledgment.
- That every external notification system honors the stop; only this runtime's
  escalation delivery does.
- Cross-platform behavior; tests ran on Linux only.

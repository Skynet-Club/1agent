# CI Matrix — Evidence (2026-11-12)

Status: **workflow defined and locally validated; not yet run on GitHub**
Scope: Linux full gates, Windows/macOS compile-level checks.

## Commands

```bash
python3 - <<'PY'  # YAML structure only
import yaml
yaml.safe_load(open('.github/workflows/ci.yml'))
PY
cargo fetch --locked
cargo check --locked --all-targets
cargo test --locked --no-run
./scripts/cross-check.sh
./scripts/verify.sh
```

## Result

- The YAML has three jobs: `linux-gates`, `windows-check` and `macos-check`.
- `cargo fetch --locked`, `cargo check --locked --all-targets` and
  `cargo test --locked --no-run` pass on the Linux host.
- `scripts/cross-check.sh` passes the Windows GNU all-targets check. macOS
  arm64 remains blocked by the host C toolchain (`ring`/`cc`), as documented
  by the script.
- `scripts/verify.sh` passes locally.

## What this proves

- The workflow file is syntactically valid and its commands run locally.
- Linux has a single CI entrypoint that reproduces the local software gates.
- Windows/macOS compile checks are defined and use the committed lockfile.

## What this does not prove

- That GitHub Actions can run the workflow (it has not been pushed/executed).
- Windows/macOS runtime behavior, ConPTY, file permissions, installers or
  performance parity.
- That the macOS runner can build the project; the local host could not.
- That a green compile job satisfies P-Gate; it does not.

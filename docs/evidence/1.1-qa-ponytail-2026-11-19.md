## 1. 这个项目做什么，按什么负载判断

1Agent 是一个本地优先、证据可审计的决策代理：模型产出答案，工具执行读写、浏览、终端和本体动作，
模型输入、工具调用与结果、验收证据写入 journal，并由 Authority/Policy、ExecutionGate 和验收门约束。

审计假设的负载：**单用户本地 CLI/TUI**，长 journal（可达数百 MB）、最多 256 个会话、
同步工具调用；不是多租户服务器，也不假设模型是可信主体。

## 2. 审计范围

深读高风险路径：类型化动作与审批、scenario merge/rollback、本体 MCP、ExecutionGate/Authority、
浏览器 egress、MCP HTTP、journal/文件工具、1ASH harness（Inspect adapter、Docker、评分、报告、安全套件）。
未逐行读完全部 16.1 万行源码；具体未读项见第 7 节。

3. **无网络浏览器可被前缀判断和模型自带 allow 名单绕过**（`src/tools/browser.rs`）✅

     回环 URL 主机；新增负例测试（`127.attacker.example`、`0.0.0.0`）。

4. **模型可伪造 `.1a/approvals` 收据自审批**（`src/tools/action.rs`、`src/tools/files.rs`）◐

     审批 CLI 也可被模型通过终端工具调用，`--actor` 是自由字符串。

      Write mandate 可执行任意命令；Execute/Network 的 strength/approval 分支成为死代码。

      Network > Execute > Write > Read 分类。`run` 新增 `--mandate-strength read-only|write|execute|network`

    - 测试：ReadOnly + `fetch_url` 拒绝；Write + `terminal_exec` 拒绝；Network/Execute 进入 approval；

## 7. 验收结论

**有条件通过（conditional pass）**。

- 作为 **1.1-dev 本地质量基线**：通过。构建、fmt、clippy -D warnings、全量测试、core-v3、claims、
  1ASH 宿主/Docker M1、30 题套件全部有证据。
- 作为 **不可信模型或多租户的安全边界**：不通过。第 4 条（审批收据未签名 + 终端同用户绕过）
  和第 13 条（journal 无哈希链）仍是结构性问题；第 15 条的网络/执行分层已补齐，但 `--authority`
  默认 read-only，需要显式 `--mandate-strength` 才能启用 web/terminal。
- 作为 **已签名 benchmark 证据**：不通过。第 14 条：报告签名与引用摘要验证未实现。

建议的下一步优先级：
1. 审批收据用现有 HMAC/签名机制绑定 out-of-band 密钥，并让 `merge_change`/`prepare_release` 验签（第 4 条）。
2. `JournalEvent` 加 `prev_hash` 并在 audit/replay 校验，补孤儿 observation（第 13 条，O2）。
3. 1ASH 报告签名 + `trace/journal/eval_log` 摘要比对（第 14 条）。

## What this proves

- A local fake HTTP MCP server completes initialize, tools/list and tools/call.
- The client records and sends `Mcp-Session-Id`.
- SSE `data:` events are parsed and matched by request id.
- Both/neither transports, remote plain HTTP and URLs with embedded
  credentials are rejected.
- Existing stdio discovery and write-gating still pass.
- A tool outcome records both `mcp_server` and `mcp_tool` in its metadata.
- `timeout_seconds` of 0 or 301 is rejected; default requests are bounded at
  20 seconds and tool execution at 25 seconds.
- HTTP and stdio responses over 2 MiB are rejected; stdio lines are read in
  bounded chunks before allocation, and non-UTF-8 bodies fail.

## What this does not prove

- Interoperability with a real third-party MCP HTTP server.
- SSE reconnection, resumability or server-initiated streams.
- OAuth discovery, token exchange, refresh or revocation.
- That a bearer token is never logged by a downstream proxy or server.
- Cross-platform behavior; tests ran on Linux only.

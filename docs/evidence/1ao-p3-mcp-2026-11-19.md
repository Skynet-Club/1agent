# 1AO P3 — Ontology MCP v0 (2026-11-19)

Scope: local stdio MCP server with read tools and opt-in typed write tools. It
is not an authenticated remote server; approval remains a human CLI act.

## Behavior

`1agent ontology mcp --journal-dir DIR` speaks JSON-RPC over stdio. With
`--workspace DIR --allow-write`, four typed action tools are added; without both,
only read tools are listed and write calls fail closed.

- `initialize` / `ping` / `tools/list` / `tools/call`.
- `ontology_types` — built-in 1AO type registry.
- `action_list` — built-in ActionType registry and approval policy.
- `ontology_read` — one object by IRI from a journal export in the configured
  journal directory; optional journal file name.
- `ontology_search` — objects of one `@type`, capped at 100.
- Journal file names cannot be absolute or contain `..`; the canonical path
  must stay inside the journal directory. Journals are capped at 64 MiB,
  request lines at 1 MiB and a single returned object at 256 KiB.
- With both flags, the server exposes `code_propose_change`, `code_run_checks`,
  `code_prepare_release` and `code_merge_change`. It never exposes
  `code_approve_change`; merge/release still require an existing human receipt.
- The server never exposes an approval or install tool.

## Limits

- No OAuth/scopes, HTTP transport, rate limits or multi-client session auth;
  stdio is local and trusts the launching user. `--allow-write` is a local
  capability flag, not a remote authorization system.
- MCP write tools use the same ExecutionGate-independent action tools as the
  agent; approval remains CLI-only, but remote per-client scope is future work.
- `ontology_search` filters on `@type`; it is not a general query language.
- Every `ontology_read`/`_search` re-exports the journal (no cache); large
  journals are expensive.
- The server does not expose Decision/Action lineage as a dedicated tool; use
  `ontology_read` with the exported IRI.

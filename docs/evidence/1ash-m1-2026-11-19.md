# 1ASH M1 — Inspect adapter and real subject smoke (2026-11-19)

Scope: M1 runner skeleton only. It runs one 1ASH task package through Inspect,
invokes a subject executable, and scores the final workspace. It is not the M2+
report/ABC/Pareto pipeline.

## Delivered

- `harness/1ash/adapter.py` — Inspect `Task`/`Solver`/`Scorer`; subject
  protocol `--task TEXT --workspace DIR --journal-dir DIR`; command and
  artifact success modules; child exit is a hard gate; safety gates are
  rejected instead of silently ignored.
- `harness/1ash/subject_1agent.sh` — real subject wrapper around
  `1agent run`. It copies the selected config into the run journal, raises only
  `max_risk` (`high` for providers supporting `execute`) and
  `permissions.allow_network` (the coding subject needs both), and leaves
  credentials referenced by path. This avoids `1agent run` rejecting
  `--config` together with `--provider`.
- `harness/1ash/tests/` — fake and no-op subjects plus two M1 task packages
  (`task-command.json`, `task-artifact.json`). Instructions now state the exact
  file content, so a correct subject is not penalised for refusing to invent
  content.
- `harness/1ash/tests/run_m1.py` — Inspect-level regression check plus Trace IR
  schema validation against a synthetic 1Agent journal.
- `harness/1ash/adapter.py` — projects the subject journal to
  `.1ash/trace.jsonl` using the closed Trace IR event set; artifact writes,
  verifications, approvals and policy denials get their own events.
- `harness/1ash/report_v0.py` / `verify_report.py` — generate a single-task
  report v0 from an Inspect log and verify its JSON Schema plus canonical
  hash-chain tip.

## Limits

- Both task packages are synthetic M1 fixtures, not benchmark tasks.
- No container or network isolation; the subject runs directly on the host and
  the task image is not used.
- Task `budget.wall_seconds` is not enforced; only the adapter `timeout_s` is.
- The real smoke used live DeepSeek through the local 1Agent config and is not
  reproducible offline. The fake/no-op check is the deterministic gate.
- `1agent run` auto-loads `~/.1a/config.json`, so CLI provider/model flags are
  ignored whenever that file exists. The wrapper works around this by using a
  copied config; the CLI override behaviour remains a product limitation.
- Safety gates are rejected, not executed.
- The report covers one synthetic task, has no signatures, no ABC checklist
  and no safety measurement; `safety_asr=0.0` is a placeholder, not a result.

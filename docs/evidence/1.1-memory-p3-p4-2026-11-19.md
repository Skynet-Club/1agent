# Evidence Memory P3/P4 v0 — 2026-11-19

Scope: `1.1-dev`, commits `7dc03b7` and `ad83373`. This is local v0 evidence,
not a model-quality benchmark.

## Implemented

- P3: `MemoryKind::Entity`/`Process`; `memory import --file|--dir` for local
  markdown/text/log files; line candidates carry `file:line` provenance,
  `untrusted` taint and secret scrubbing, and never auto-activate.
- P3: `MemoryQuery` adds CJK bigrams, kind metadata matching and
  `since_ms`/`until_ms` bounds; `memory recall` exposes all three filters.
- P3: `harness/1ash/memory/` seeds `MEMORY.md` and scores `answer.txt` for
  preference recall, update, temporal, stale preference and multi-session
  project tasks.
- P4: `MemoryScope::matches` hierarchical visibility (a broad record is visible
  to a narrow query, never the reverse); `UserModel`, `MemoryService::get` and
  recall use it.
- P4: `onboard`/`memory recall` accept tenant/workspace/ticket scope; full
  runs and memory tools read defaults from `ONEAGENT_TENANT_ID`,
  `ONEAGENT_WORKSPACE_ID` and `ONEAGENT_TICKET_ID`.

## Not verified / remaining

- LongMemEval/PersonaMem/MemoryArena/PIVOT tasks and a real memory-off vs
  memory-on vs long-context comparison are not implemented. The synthetic
  family validates harness shape only.
- Embeddings are intentionally not added; the decision waits for that external
  evaluation.
- Shared memory is read-visibility only; object-level ACL, multi-agent write
  conflict handling and a tenant-management CLI remain.
- TUI end-to-end memory question with a real provider was not rerun in this
  slice; the P0 CLI journal evidence remains in the prior memory checkpoint.

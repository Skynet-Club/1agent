# 0.98 Onboarding + CLI IA

Status: **draft for implementation**  
Date: 2026-11-14  
Branch: `0.98-dev`  
Parent plan: `docs/0.98-development-plan.md`  
Related ADRs: 0132 (CLI IA), 0133 (setup/config/secret), 0134 (permission presets)

## 0. Scope

This document defines the first 0.98 vertical slice:

1. `1agent setup` guided first run: idempotent, resumable, `--check`, non-interactive.
2. Provider choice: DeepSeek / OpenAI-compatible / Ollama.
3. Masked key input, `/v1/models` probe, 0600 storage.
4. Permission presets: `read-only` / `safe` / `full-local`.
5. Workspace/read roots, 30-second smoke task, journal path, `doctor` summary.
6. Public command layer (13 commands), advanced commands behind `help advanced`/`--all`.
7. `1agent status`: version/platform/model/permissions/data dir/last run.
8. Shell completions, man page, consistent `--json`, `error:` + `next:`.

Acceptance: a new user completes the first successful task in ≤5 minutes with no
manual file edits; setup is idempotent; read-only refusal is explicit.

Non-goals: browser/CUA, MCP OAuth, skill eval/canary, daemon ledger. Those are
slices 2–5 and must not leak into this slice.

## 3. Setup state machine

### 3.1 States

```text
preflight -> provider -> credentials -> model -> permissions -> workspace -> smoke -> doctor -> done
```

Each state:

1. Reads current config/state and computes desired state.
2. Writes only the diff (idempotent).
3. Atomically updates `$ONEAGENT_HOME/setup.json`.
4. On failure, prints `error:` + `next:` and keeps the completed prefix.
5. `--check` computes the same state but never writes and never prompts.
6. SIGINT saves the current step and exits 130; `--resume` continues.

### 3.2 Flags

```text
1agent setup
  --check                     read-only readiness check; no writes, no prompts
  --probe                     with --check, allow the provider /v1/models probe
  --non-interactive           never prompt; require explicit values
  --yes                       accept defaults where a value is optional (non-TTY only)
  --resume                    continue from setup.json
  --force                     overwrite an existing config/profile after backup
  --root <PATH>               runtime home (default $ONEAGENT_HOME or $HOME/.1a)
  --provider <NAME>           deepseek | openai-compatible | ollama
  --base-url <URL>            provider base URL
  --model <MODEL>             model id
  --api-key-stdin             read the key from stdin; never from argv
  --permission-preset <NAME>  read-only | safe | full-local
  --workspace <PATH>          default workspace/read root
  --read-root <PATH>          repeatable additional read root
  --skip-probe                skip /v1/models; require --model
  --skip-smoke                skip the 30-second smoke task; records why
  --json                      machine-readable output
```

Test-only hidden value: `--provider deterministic` for offline E2E. It is not
advertised in help and must not be used in documentation as a real provider.

### 3.3 State file

`$ONEAGENT_HOME/setup.json`, 0600, atomic write (temp + fsync + rename):

```json
{
  "schema": "1agent.setup.v1",
  "current_step": "doctor",
  "completed": [
    "preflight",
    "provider",
    "credentials",
    "model",
    "permissions",
    "workspace",
    "smoke",
    "doctor"
  ],
  "config_hash": "sha256:<hex>",
  "updated_at_unix_ms": 1763122800000,
  "last_error": null
}
```

Rules:

- `completed` is append-only; a repeated step is a no-op if the desired state
  matches.
- `config_hash` is the SHA-256 of the canonical config JSON; `--check` uses it
  to detect drift.
- `last_error` is `{code, message, next}` or null; it does not contain secrets.
- If `setup.json` is corrupt, it is ignored and rebuilt from the current
  desired state (the corrupt file is left untouched for inspection).

### 3.4 Idempotency

`setup` is idempotent by desired state, not by “already ran”:

- Existing home with matching config → no file writes; prints `already ready`.
- Existing key file with matching provider → keep; do not re-prompt.
- Existing config with different model → update only that field.
- `--force` creates a timestamped backup before replacing.

The second run must produce **0 byte changes** to `config.json`, `setup.json`
(except `updated_at`), and key files. Tests compare file hashes.

### 3.5 Non-interactive and TTY

- `setup` with no TTY and no flags → exit 2:
  `error: setup requires a TTY or explicit flags`
  `next: 1agent setup --non-interactive --provider deepseek --model ...`
- `setup --non-interactive` requires provider, model (unless `--probe` can
  discover one), permission preset, and workspace; missing values → exit 2.
- `--yes` only accepts defaults; it does not invent a provider or key.
- A bare `1agent` on a fresh home prints a short welcome and `next: 1agent setup`;
  it does not auto-run setup or hang.
- `--json` works without a TTY and never prompts.

### 3.6 Interactive wizard (0.98)

When stdin/stdout are TTYs and none of `--check`, `--json`,
`--non-interactive`, or `--yes` is set, `setup` opens a full-screen wizard.
It is the default first-run surface; the flags above keep the scriptable path
unchanged.

Screens:

1. **Welcome** — 1AGENT wordmark, version/theme, and what will happen.
2. **Provider** — DeepSeek / OpenAI-compatible / Ollama menu.
3. **Endpoint** — only for OpenAI-compatible; keep current, OpenAI default,
   or enter a URL.
4. **Credential** — only when the provider needs a key; keep an existing key
   or enter a new one (masked). Loopback endpoints do not require a key.
5. **Model** — models come from `/v1/models`; the configured model is kept and
   marked `not advertised` when the provider no longer lists it. Manual entry
   is the last option.
6. **Permissions** — read-only / safe / full-local with one-line
   consequences.
7. **Workspace** — current workspace, current directory, home, or another
   existing path.
8. **Review** — all choices, then Run setup / Back / Cancel.

Keyboard: `↑/↓` or `j/k` move, `1-9` jump, `Enter` select, `Esc` back,
`Ctrl-C` cancel (exit 130). The wizard never writes config; `run_setup`
remains the single writer. The alternate screen and raw mode are restored on
every exit path, including cancel and panic.

Visual contract:

- Military-green palette shared with the TUI: `#3fb950` accent, `#4a7855`
  lines, `#5e9e5e` body, `#3a5c42` shadow. `NO_COLOR` and `TERM=dumb` disable
  color.
- The full 1AGENT block wordmark is used at ≥62 columns; a compact
  `1 · A G E N T` wordmark below that. The layout is width-aware and truncates
  long values instead of wrapping.
- The API key is masked (`•`), never echoed, never shown in the review, and
  never written to stdout or the journal.

Model discovery details:

- The probe runs after the credential is known, matching the state-machine
  order (provider → credentials → model).
- Model preference is explicit `--model`, then the existing configured model,
  then the first advertised model. A configured model is never silently
  replaced by the first advertised one.
- An unadvertised selected model is `missing` in `--check` (not ready) and
  `warn` in a normal setup; the setup does not claim it is ready.
- A successful probe is passed to `run_setup`, so setup does not issue a
  second `/v1/models` request.
- Probe failure is recoverable: Retry, enter a model id manually, or keep the
  current model. With `--skip-probe` or `--api-key-stdin`, the wizard skips
  the probe and the smoke run validates the key/model.
- Existing config is prefilled; a second identical run leaves `config.json`
  byte-identical.

Evidence: `docs/evidence/0.98-setup/wizard-e2e.md`.

## 4. Config v2

### 4.1 Schema

Backward compatible: `schema_version` is optional and defaults to 1.
`schema_version: 2` adds the optional top-level fields below.

```json
{
  "schema_version": 2,
  "default_provider": "deepseek",
  "workspace": "/home/user/work",
  "permissions": {
    "preset": "safe",
    "read_roots": ["/home/user/work"],
    "allow_network": false
  },
  "providers": [
    {
      "id": "deepseek",
      "adapter": "open_ai_compatible",
      "model": "deepseek-chat",
      "base_url": "https://api.deepseek.com/v1",
      "api_key_env": "DEEPSEEK_API_KEY",
      "api_key_file": "/home/user/.1a/keys/provider-deepseek.key"
    }
  ]
}
```

New fields:

- `schema_version` (default 1)
- `default_provider` (provider id; default first provider)
- `workspace` (absolute path; default cwd)
- `permissions.preset` (`read-only|safe|full-local`; default `safe`)
- `permissions.read_roots` (absolute paths; default `[workspace]`)
- `permissions.allow_network` (default false)
- `ProviderConfig.api_key_file` (absolute path; optional)

`deny_unknown_fields` stays. Unknown fields still fail closed.

### 4.2 Loading and precedence

Default config path: `$ONEAGENT_HOME/config.json` if it exists. `--config`
overrides. If neither exists, existing behavior is unchanged (provider via
flags/env).

Provider value precedence:

```text
explicit CLI flag (deprecated for api-key) > config api_key_file > api_key_env > missing
```

Model precedence:

```text
explicit --model > config providers[default_provider].model > first provider model
```

Permission precedence:

```text
explicit --read-only / --allow-network / --read-root
  > config permissions
  > safe defaults (write on, network off, workspace=cwd)
```

### 4.3 Migration

- Reading v1 config: fill defaults; do not rewrite the file until `setup` or
  `permissions set` updates it.
- Writing v2: atomic write; old file backed up to `config.json.v1.bak` on the
  first migration.
- `1agent upgrade` does not rewrite provider config; it only repairs the home
  layout.
- If `default_provider` is missing or unknown → `config.default_provider_invalid`
  with `next: 1agent model use <id>`.

## 5. Provider setup

### 5.1 Presets

| Preset | Adapter | Base URL | Probe | Notes |
|---|---|---|---|---|
| DeepSeek | `open_ai_compatible` | `https://api.deepseek.com/v1` | `GET /models` | API key required |
| OpenAI-compatible | `open_ai_compatible` | user-supplied | `GET <base>/models` or `<base>/v1/models` | works with any compatible endpoint |
| Ollama | `open_ai_compatible` | `http://127.0.0.1:11434/v1` | `GET /models`, fallback `GET /api/tags` | loopback HTTP allowed, no key |

The setup UI never prints a key. It displays `credential: present` or
`credential: missing`.

### 5.2 `/v1/models` probe

Algorithm:

1. Normalize `base_url` (trim trailing `/`).
2. If it ends with `/v1`, request `<base>/models`; otherwise request
   `<base>/v1/models`. For Ollama, fallback to `<origin>/api/tags`.
3. HTTPS required; HTTP allowed only for loopback (`127.0.0.1`, `::1`,
   `localhost`). Redirects are disabled.
4. Timeout 5s; bearer key only if one is present; never put the key in a URL.
5. Parse OpenAI shape `{"data":[{"id":"..."}]}`; Ollama tags shape
   `{"models":[{"name":"..."}]}`.
6. On success, present a sorted model list; on empty, require `--model`.
7. On failure, map to:
   - `provider.unreachable` → `next: 1agent model test`
   - `provider.auth` → `next: re-enter key with 1agent setup --resume`
   - `provider.redirect_refused` → `next: use the final HTTPS base URL`
   - `provider.models_empty` → `next: pass --model <id>`

`--skip-probe` requires `--model`; `--check` does not probe unless `--probe`.

### 5.3 Key storage

- Path: `$ONEAGENT_HOME/keys/provider-<id>.key`; directory 0700, file 0600.
- Reuse the TUI save path and permission checks; extract to `provider_profile`.
- Write: `O_NOFOLLOW`, `O_CREAT|O_EXCL` for new, temp + fsync + rename for
  replace; refuse symlinks and non-regular files.
- Content: raw key, optional trailing newline; trim only trailing CR/LF.
- Input: masked prompt; `--api-key-stdin` for automation. `--api-key <value>`
  is rejected by `setup` with `error: setup.api_key_argv_forbidden` and
  `next: use --api-key-stdin`.
- Never log, never include in JSON, never write to the journal.
- Config stores `api_key_file` (path), not the key. `api_key_env` may remain as
  a fallback.

### 5.4 Smoke task

- Budget: 30 seconds wall clock, 16 output tokens, one provider call.
- Prompt: “Reply with OK.”
- Success: HTTP 2xx and a non-empty answer; journal written under
  `$ONEAGENT_HOME/journals/`.
- Failure: setup exits 1 with `error: setup.smoke_failed`, `next: 1agent model test`;
  the completed prefix remains resumable.
- `--skip-smoke` records `smoke: skipped` and the reason; `setup --check`
  reports `smoke: unverified`.

## 6. Permission presets

Presets are sugar over the existing `PermissionSet` + `Authority`; they are not
a second policy path.

| Preset | allow_write | allow_network | terminal | approvals | irreversible |
|---|---|---|---|---|---|
| `read-only` | false | false | no | n/a | n/a |
| `safe` | true (workspace only) | false by default | requires approval | network/execute/high-risk | **always confirm** |
| `full-local` | true (workspace + explicit roots) | true | yes | routine actions not prompted | **always confirm**; KILL always effective |

Rules:

- `read-only` maps to the existing `--read-only`: write/terminal tools hidden,
  network tools blocked. A write attempt returns
  `error: permission.read_only`, `next: re-run with a writable preset`.
- `safe` runs with `allow_write=true`, `allow_network=false` by default. Enabling
  network requires `--allow-network` or `permissions set --network on` with
  approval. `Authority::RequireApproval` remains fail-closed: in headless mode
  it returns `approval_required`; it never auto-approves.
- `full-local` sets `allow_write=true`, `allow_network=true`; routine approvals
  are off, but irreversible actions still require confirmation (browser slice
  2) and `KILL` still blocks write tools.
- `permissions explain` prints the preset, resolved `PermissionSet`, authority
  profile, visible/hidden tools, and the exact config paths.
- `permissions set` writes config v2 atomically and prints a diff; it does not
  silently widen network access.
- The preset is stored, but `setup --check` recomputes the resolved set and
  reports drift.

## 8. Output contract

### 8.1 JSON envelope

Success:

```json
{"schema":"1agent.cli/v1","ok":true,"data":{...}}
```

Failure:

```json
{
  "schema": "1agent.cli/v1",
  "ok": false,
  "error": {
    "code": "setup.provider_unreachable",
    "message": "provider did not respond within 5s",
    "next": "1agent model test --provider deepseek",
    "details": {"base_url": "https://api.deepseek.com/v1"}
  }
}
```

Rules:

- stdout contains exactly one JSON value when `--json` is set.
- logs/progress go to stderr.
- `details` must not contain secrets; paths are allowed.
- `code` is stable and namespaced (`setup.*`, `provider.*`, `permission.*`,
  `config.*`, `status.*`).

### 8.2 Human errors

```text
error: provider did not respond within 5s
next: 1agent model test --provider deepseek
```

- `error:` and `next:` go to stderr.
- stdout contains only the result (answer, status lines, file path).
- No mixed Chinese/English prefixes in the same command; `setup`/`status` use
  English CLI tokens, existing TUI messages remain unchanged.

### 8.3 Exit codes

| Code | Meaning | Applies to |
|---|---|---|
| 0 | success / ready | all |
| 1 | runtime/task failure | all |
| 2 | usage / missing flags / not ready | new commands; legacy where already used |
| 3 | reserved for policy/approval denial | not emitted by setup/status yet; ADR required |

Legacy commands keep their current exit behavior until migrated; the contract
above is enforced for `setup`, `status`, `model`, `permissions`, `skills`,
and the new `run` approval path.

## 9. Completions and man page

- `1agent completions <bash|zsh|fish|powershell|elvish>` writes the script to
  stdout; generated from the live clap command tree.
- `1agent man` writes a roff man page to stdout (currently a static draft;
  `clap_mangen` migration is pending).
- Both are advanced commands (hidden from public help) but documented in the
  manual and included in the package under `share/completions/` and
  `share/man/man1/`.
- Completions are generated from the live clap tree; the man page is a static
  draft until `clap_mangen` is adopted. Tests assert:
  - bash output contains `1agent` and `setup`;
  - zsh output starts with `#compdef 1agent`;
  - fish output contains `complete -c 1agent`;
  - man output contains `.TH` and `setup`.
- `scripts/package.sh` copies the generated files into the package and
  `SHA256SUMS` covers them.

## 11. Open questions

1. Exit code `3` for policy/approval denial: accept, or keep `1` for
   compatibility?
2. `--provider deterministic` as a hidden test-only value: accept, or put it
   behind `cfg(test)` and use a separate test binary?
3. Should `setup` create a default `config.json` even when the user later uses
   `--config`? Proposal: yes, but `--config` remains the override.
4. Should `status` read the newest journal automatically, or require a
